# CMDB 云资源管理平台全量重写设计

## 1. 背景与目标

CMDB 将从偏传统机房服务器的配置管理系统，重写为以业务项目为最高管理边界的云资源管理平台。新版本不兼容现有业务模型、接口、页面或数据库结构，也不迁移旧数据。

首期目标是打通以下完整闭环：

1. 创建业务项目并配置项目成员权限。
2. 在项目内接入阿里云账号、AWS 账号或 Kubernetes 集群。
3. 每小时自动同步或手工同步指定类型的云资源。
4. 统一查询资源基础信息、访问端点、资源关系和同步状态。
5. 对失联、恢复和删除等资源生命周期事件进行审计。

项目保留 Go + Gin、Vue 3 + TypeScript、MySQL 和 Docker Compose 技术栈，但代码、数据库及用户界面全部重新实现。

## 2. 设计原则

- 业务项目是最高级的数据、权限和资源归属边界。
- 一个接入源及其同步得到的资源只能归属于一个项目。
- 云平台是云端原始属性的事实来源，CMDB 不允许手工修改这些属性。
- 公共能力统一实现，平台差异由独立接入模块封装。
- 所有新增代码文件、结构体、接口、公开函数、核心业务分支和复杂逻辑均提供准确的中文注释。
- 凭证、日志和接口响应遵循最小暴露原则。
- 首期只实现已经确认的资源类型，不提前扩展成本、告警或审批能力。

## 3. 业务层级与权限

系统业务层级如下：

```text
业务项目 → 云账号或 Kubernetes 集群 → 区域 → 云资源
```

云厂商中的 Project 或 Tenant 属于平台接入信息，不取代 CMDB 的业务项目。

项目包含名称、全局唯一编码、描述、可选负责人、启停状态、成员和审计信息。项目负责人字段可以为空。资源本身不维护负责人。

项目级角色包括：

- 系统管理员：管理所有项目和系统配置。
- 项目管理员：管理本项目的接入源、同步策略和成员。
- 项目成员：查看本项目资源并执行手工同步。
- 只读成员：只能查看本项目资源。

用户不能查看未加入项目的资源、接入源、同步记录和审计信息。停用项目后停止其自动同步，已有资源保留并允许只读查看。

## 4. 总体架构

新 CMDB 采用模块化单体架构，各模块在同一个服务中运行并保持清晰边界：

- 项目模块：项目资料、负责人、成员和项目角色。
- 接入源模块：平台连接配置、加密凭证、连接测试及同步设置。
- 云资源核心模块：统一资源身份、公共属性、状态和平台扩展属性。
- 访问端点模块：统一保存 IP、域名、端口、协议和域名解析结果。
- 资源关系模块：统一保存资源之间的包含、运行于、暴露等关系。
- 平台采集模块：阿里云、AWS、Kubernetes 的认证、采集、分页和字段转换。
- 同步任务模块：定时与手工触发、并发控制、结果统计和错误摘要。
- 生命周期模块：失联标记、资源恢复及三天后的物理删除。
- 权限与审计模块：项目隔离、凭证保护和关键操作留痕。

三个平台采集模块必须通过统一接口写入云资源核心，不得各自重复实现项目、权限、审计或清理逻辑。

## 5. 首期资源范围

### 5.1 阿里云

- ECS
- RDS
- 负载均衡

ECS 采集网卡上的全部内网和公网 IP。RDS 与负载均衡保存平台返回的内外网连接域名、端口以及最近一次解析得到的 IP 集合。

### 5.2 AWS

- EC2
- RDS
- ELB

EC2 采集网卡上的全部内网和公网 IP。RDS 与 ELB 保存 AWS 返回的内外网 DNS 名称、端口以及最近一次解析得到的 IP 集合，不将动态解析地址误认为固定资产属性。

### 5.3 Kubernetes

- 集群
- Namespace
- Node
- Workload
- Pod
- Service
- Ingress

Kubernetes 模块采集 Node 地址、Pod IP、Service 的 ClusterIP、ExternalIP 和 LoadBalancer 地址，以及 Ingress 地址，并建立集群内资源关系。

## 6. 核心数据模型

### 6.1 项目

保存项目名称、唯一编码、描述、可选负责人、启停状态、创建时间、更新时间和审计信息。

### 6.2 项目成员

保存项目、用户和项目角色的关联。同一用户在同一项目中只能存在一个有效角色。

### 6.3 接入源

保存所属项目、平台类型、显示名称、加密凭证、同步周期、启停状态、最后同步时间和最后同步状态。接入源只能属于一个项目，默认同步周期为一小时。

### 6.4 云资源

保存所属项目、接入源、平台、资源类型、云端唯一 ID、名称、区域、可用区、运行状态、生命周期状态、平台扩展属性、首次发现时间、最后发现时间和失联时间。

“接入源 + 资源类型 + 云端唯一 ID”构成唯一约束。生命周期状态至少包含“正常”和“已失联”，运行状态保留云平台的原始业务含义。

### 6.5 访问端点

保存所属资源、内网或公网类别、IP 或域名类别、原始地址、端口、协议、最近解析的 IP 集合和解析时间。一个资源可以拥有多个访问端点。

### 6.6 资源关系

保存源资源、目标资源和关系类型，用于表达 Namespace 包含 Pod、Workload 管理 Pod、Service 暴露 Workload 等关系。

### 6.7 同步任务

保存接入源、触发方式、开始时间、结束时间、执行状态、各资源类型统计和安全过滤后的错误摘要。

### 6.8 审计日志

保存操作人、项目、对象类型、对象 ID、动作、结果和安全过滤后的变更内容。资源物理删除后，相关审计日志继续保留。

## 7. 凭证安全

阿里云 AccessKey、AWS 凭证和 Kubernetes kubeconfig 使用 CMDB 主加密密钥加密后存入数据库。主加密密钥通过部署环境变量 `CMDB_ENCRYPTION_KEY` 提供，不写入数据库、源代码或代码仓库。

系统遵循以下安全规则：

- API 和页面不返回凭证明文或完整密文，只显示必要的脱敏信息。
- 凭证仅在执行连接测试或同步任务时在内存中临时解密。
- 新增、更新和测试凭证的行为写入审计日志，但日志不包含敏感值。
- 主加密密钥丢失后，已有凭证不可恢复，需要重新录入。

## 8. 同步流程

接入源启用后默认每小时自动同步，也允许有权限的项目成员手工触发。单个接入源同一时间只允许运行一个同步任务，不同接入源可以并行执行。

单次同步流程如下：

1. 解密凭证并验证连接。
2. 按资源类型分别采集并处理分页、限流和平台错误。
3. 将平台数据转换为统一云资源、访问端点和资源关系。
4. 按唯一约束新增或更新资源。
5. 对本次成功完成采集但未再次出现的资源标记为已失联。
6. 对三天内重新出现的资源恢复原记录，并清除失联状态。
7. 记录各资源类型的新增、更新、恢复、失联和失败数量。

同步安全规则如下：

- 单类资源采集失败时，不对该类型执行失联判定。
- 部分资源类型失败时，任务标记为“部分成功”，成功类型仍正常入库。
- 接入源认证失败时，不更新任何资源的失联状态。
- 重复触发正在运行的接入源时，拒绝新任务并返回明确提示。

独立清理任务定期检查已失联资源。资源连续失联满三天后执行物理删除，同时删除其访问端点和资源关系，但保留审计日志。接入源和项目不随资源清理任务自动删除。

## 9. API 与页面结构

后端接口以项目作为强制上下文，并按模块组织：

```text
/api/v1/projects
/api/v1/projects/:projectId/sources
/api/v1/projects/:projectId/resources
/api/v1/projects/:projectId/aliyun
/api/v1/projects/:projectId/aws
/api/v1/projects/:projectId/kubernetes
/api/v1/projects/:projectId/sync-jobs
/api/v1/projects/:projectId/audit-logs
```

前端主要页面包括：

- 项目管理：项目列表、详情、负责人、成员和角色配置。
- 云资源总览：资源数量、平台与类型分布、生命周期状态和最近同步状态。
- 阿里云模块：账号配置、连接测试、资源列表和同步记录。
- AWS 模块：账号配置、连接测试、资源列表和同步记录。
- Kubernetes 模块：集群配置、连接测试、集群资源树和同步记录。
- 统一资源搜索：按名称、云端 ID、类型、区域、状态、IP 或域名搜索。
- 资源详情：公共属性、平台扩展属性、访问端点、资源关系和审计记录。
- 同步任务：任务状态、触发方式、分类结果和错误摘要。
- 审计日志：按项目、操作人、模块、对象和时间筛选。

## 10. 用户界面方向

新 UI 采用现代云管理控制台风格：

- 左侧分组导航，顶部放置项目切换、全局搜索和用户菜单。
- 首页使用简洁数据卡片、必要的资源分布图和同步状态，不堆叠装饰性图表。
- 阿里云、AWS 和 Kubernetes 分别作为一级模块展示。
- 资源列表使用高密度表格，并提供筛选、排序、分页和列配置。
- 资源详情使用概览、端点、关系、原始属性和审计记录等标签页。
- 采用浅色、低饱和的中性色体系，平台色只用于识别。
- 完整覆盖加载、空数据、失败、无权限和失联等交互状态。
- 首期适配常见桌面分辨率并保证平板可用，不进行手机端专项设计。

## 11. 全量重写策略

旧版 CI 类型、CI 实例、SSH 发现、变更管理、快照、拓扑、系统集成、认证、用户管理、权限、接口、页面和数据库结构均不复用。新系统从空数据库初始化，不提供旧数据迁移或兼容层。

全量重写仍需分阶段交付，每个阶段保持代码可构建、测试可执行：

1. 新工程骨架、数据库迁移、认证和统一基础能力。
2. 项目、项目成员及项目级权限。
3. 接入源、凭证加密和同步任务框架。
4. 统一资源、端点、关系和生命周期。
5. 阿里云、AWS、Kubernetes 三个平台采集模块。
6. 现代化前端页面和完整联调。
7. Docker Compose 部署、真实环境连接验证和验收。

旧业务代码和数据库定义在新功能具备对应基础能力后统一移除，最终交付物中不保留旧版入口或兼容代码。

## 12. 错误处理与可观测性

- API 使用统一响应结构和稳定错误码，前端展示可理解的中文错误信息。
- 云平台限流、认证失败、权限不足、网络超时和部分响应分别记录明确分类。
- 日志和同步错误摘要必须过滤密码、令牌、AccessKey、kubeconfig 及主加密密钥。
- 同步任务保留资源类型级统计，便于判断失败范围和重新执行。
- 关键状态变化写入审计日志，包括项目权限调整、接入源变更、手工同步、资源失联、恢复和删除。

## 13. 测试与验收

后端测试覆盖：

- 项目权限和跨项目数据隔离。
- 同步幂等、并发限制和部分成功。
- 失联、三天内恢复及满三天清理。
- 凭证加解密与敏感数据过滤。
- 三个平台的字段映射、端点转换和资源关系转换。

前端测试覆盖：

- 项目切换与项目权限。
- 资源搜索、筛选和详情展示。
- 接入源连接测试和同步状态。
- 加载、空数据、失败、无权限和失联状态。

平台采集器使用接口与模拟响应完成自动测试。真实阿里云账号、AWS 账号和 Kubernetes 集群只用于独立连接验证，不作为自动测试运行条件。

最终验收必须通过后端测试、前端测试、TypeScript 类型检查、生产构建和 Docker Compose 启动验证。

## 14. 首期明确不包含

- 旧数据迁移与旧接口兼容。
- 传统机房服务器和 SSH 自动发现。
- 成本与账单管理。
- 告警管理。
- 变更申请和审批流。
- 手机端专项适配。
- 首期范围之外的云平台和资源类型。
