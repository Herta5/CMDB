# CMDB PostgreSQL 17 替换设计

## 目标与边界

CMDB 将数据库从 MySQL 8.4 完整替换为 PostgreSQL 17。切换使用全新的空数据库，不迁移任何 MySQL 数据。应用、权限、云同步、三类资产表、24 小时失联清理和审计规则保持不变。

切换完成并通过运行态验收后，删除旧 MySQL 容器及 `cmdb-mysql-data` 数据卷。该删除不可恢复。PostgreSQL 使用独立持久卷，宿主机开放标准端口 `5432`；CMDB Web 服务继续开放 `80`。

## 账号与安全

采用双账号模式：

- `postgres` 是数据库管理员，只用于容器初始化和管理操作，不提供给 CMDB 应用。
- `cmdb` 是权限受限的应用账号，只能连接 CMDB 数据库并操作其业务 schema、表和序列。
- 管理员密码与应用密码分别由部署环境提供，不写入仓库、日志、测试快照或接口。
- 应用账号不得创建数据库、创建角色或访问其他业务数据库。

## 数据结构与 SQL 方言

- 主键使用 `BIGINT GENERATED BY DEFAULT AS IDENTITY`。
- 状态字段使用 `VARCHAR` 和 `CHECK` 约束，避免维护 PostgreSQL 自定义枚举类型。
- JSON 数据使用 `JSONB`，包括原始属性、IP 数组、访问端点、同步统计和审计详情。
- 时间字段使用 `TIMESTAMPTZ(3)`，数据库和应用统一按 UTC 处理。
- `updated_at` 由 GORM 在更新时维护，数据库只提供初始默认值。
- 外键、唯一约束、项目权限边界和中文表字段注释保持完整。
- 三类资产表名保持为 `resources_servers`、`resources_databases` 和 `resources_load_balancers`。

## 应用适配

后端使用 GORM PostgreSQL 驱动和 PostgreSQL DSN，默认端口改为 `5432`。删除 MySQL 驱动、MySQL 错误类型及 MySQL 专用判断；重复键统一依赖 GORM 翻译后的 `gorm.ErrDuplicatedKey`，并使用 PostgreSQL 错误码作为兼容保护。

初始化 SQL 全部改写为 PostgreSQL 语法，不保留 MySQL 增量迁移链。新数据库按照固定顺序创建管理员无法被应用使用的数据库边界、受限 `cmdb` 角色、业务 schema、表、索引、外键、检查约束和中文注释。SQLite 仍只用于快速单元测试，另增加 PostgreSQL 初始化结构与真实容器验收。

## 部署与切换

Docker Compose 使用 `postgres:17`，数据库健康检查改为 `pg_isready`，持久卷改为 `cmdb-postgresql-data`，宿主机发布 `5432:5432`。环境变量保留通用 `DB_HOST`、`DB_PORT`、`DB_USER`、`DB_PASSWORD`、`DB_NAME`，新增仅供初始化的 PostgreSQL 管理员密码变量。

切换按以下顺序执行：

1. 完成驱动、配置、SQL、Compose、文档和自动化测试。
2. 停止旧 CMDB 应用与 MySQL 容器。
3. 启动全新 PostgreSQL 17 和 CMDB 应用。
4. 验证双账号权限、表结构、中文注释、健康接口和首个管理员创建流程。
5. 确认 PostgreSQL 运行正常后，删除旧 MySQL 容器和 `cmdb-mysql-data` 数据卷。

## 错误处理与回退边界

数据库连接失败时应用必须启动失败并输出不含密码的可操作错误。初始化失败时保留 PostgreSQL 数据卷用于诊断，不删除 MySQL 数据卷。只有 PostgreSQL 的结构、权限、应用健康和核心流程全部验收通过后，才允许执行不可恢复的 MySQL 数据卷删除；删除完成后不提供旧数据回退。

## 测试与验收

- 后端运行 `go test ./...` 并完成 Linux 生产构建。
- 前端运行完整 Vitest、TypeScript 类型检查和生产构建。
- 初始化结构测试验证 PostgreSQL 方言、全部业务表、约束和中文注释。
- 真实 PostgreSQL 容器验证应用连接、CRUD、重复键转换、JSONB、时区字段和级联删除。
- 权限测试验证 `cmdb` 账号不能创建数据库、角色或访问非 CMDB 目标。
- 运行态验证 80 端口健康、5432 对外开放、MySQL 容器与旧数据卷均不存在。
- 空库不预置用户，部署后使用初始化命令重新创建首个系统管理员。
