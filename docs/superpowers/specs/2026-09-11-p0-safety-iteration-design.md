# CMDB P0 安全一致性迭代设计

## 状态

- 设计日期：2026-09-11。
- 设计结论：各部分已由用户逐项确认。
- 实施范围：项目与接入源删除保护、云账号唯一归属与接入校验、同步失败状态与自动调度修正。

## 背景

现有 CMDB 已具备项目、接入源、阿里云与 AWS 采集、三类资产、同步任务和审计主流程，但实现状态中仍有三组会破坏核心业务红线的 P0 差距：

1. 项目或接入源可以借数据库级联删除资产，绕过资源连续失联满 24 小时且经成功采集再次确认的物理删除规则。
2. 接入源缺少稳定云账号标识、平台级凭证与配置严格校验，无法保证同一云账号只归属于一个项目。
3. 全部资源类型分别失败时会被误判为部分成功，自动失败任务也不会推进下次计划，可能同时造成错误的成功语义和无间隔重试。

本轮优先修复以上三组安全与一致性缺口。资源列表、停用项目完整运行边界、易变端点观测等其他已记录差距不在本轮范围内。

## 目标与成功标准

- 新建接入源和显式替换凭证时，必须先通过平台校验并联网取得稳定云账号 ID；无法识别身份时不保存任何变更。
- 同一平台的同一稳定云账号 ID 在 CMDB 中只能对应一条已验证接入源，不能借不同名称、凭证或项目重复接入。
- 历史接入源升级后处于明确的“待验证”状态，只能读取；通过专门的身份验证动作后才恢复普通管理和同步能力。
- 项目或接入源存在任一三类资产，或存在排队、运行任务时，删除稳定返回 `409`，系统管理员也不能绕过。
- 同步终态由成功类型数和失败类型数确定：没有任何成功类型时必为失败；自动失败推进下次计划，手工和重试失败不改变自动计划。
- 生产应用账号不拥有 DDL 权限，应用启动只检查数据库结构版本；已有数据卷由运维显式执行一次性管理员迁移命令升级。
- 所有新增与变化先由失败测试定义，最终通过后端全量测试、PostgreSQL 17 集成测试、前端全量测试、类型检查、生产构建和已有数据卷升级演练。

## 设计原则

- 平台模块只负责本平台的字段契约、云 API 调用、账号识别和采集；项目归属、唯一性、凭证加密、事务、同步状态和审计仍由共享核心负责。
- 业务服务提供友好的前置校验，PostgreSQL 约束提供并发和异常路径下的最终保护；两者缺一不可。
- 失败路径默认不改变资产事实，不泄露云平台原始错误，也不把调度推进误写为同步成功。
- 数据升级必须显式、可重复判断且失败即停止，不允许生产应用启动时隐式改表。

## 平台适配边界

### `ProviderAdapter`

共享资源核心引入统一的 `ProviderAdapter`，由阿里云和 AWS 模块分别实现。接口提供以下能力：

- 校验凭证 JSON 的字段集合、类型、必填项和非空值；
- 校验非敏感配置 JSON；
- 使用轻量云 API 返回稳定的云账号 ID；
- 暴露该平台首期支持的资源类型，并继续提供既有轻量连接测试和完整采集能力。

适配器不查询项目、不判断账号是否重复、不写数据库、不加密凭证，也不记录审计。共享资源服务根据 `provider` 选择适配器，完成项目归属、唯一性、事务、错误映射与审计。

### 平台字段白名单

- 阿里云凭证只接受完整的 `access_key_id`、`access_key_secret`。
- AWS 凭证只接受完整的 `access_key_id`、`secret_access_key`，可选 `session_token`。
- 必填字段缺失、值不是字符串、空白字符串或出现未知字段时，均返回稳定中文参数错误。
- 首期没有区域之外的平台扩展配置，因此 `config` 只允许空对象；缺失值规范化为 `{}`，含任意业务字段时拒绝。
- 共享敏感键分类在递归检查中拦截密码、令牌、AccessKey、主密钥、密文、Authorization、原始错误正文等敏感键，避免未来扩展配置时把秘密写入非凭证字段。平台白名单不能弱化共享拦截。

所有校验都在加密和持久化之前完成。接口、日志、测试失败输出和审计只保留中文安全分类，不回显输入值、云 SDK 原始错误或密文。

### 稳定账号身份

- 阿里云通过 STS `GetCallerIdentity` 取得账号 ID。
- AWS 通过 STS `GetCallerIdentity` 取得 12 位 Account ID。
- 身份识别只使用最小请求，不遍历资源；测试以接口和模拟响应完成，不连接真实账号。
- 返回值为空、格式不合法、认证失败、权限不足、超时或网络失败时，身份识别失败。创建或凭证替换必须整体失败，不得保存未验证接入源或新密文。

## 接入源领域模型与流程

### 数据字段

`resource_sources` 新增：

| 字段 | 含义 |
| --- | --- |
| `cloud_account_id` | 平台返回的稳定云账号 ID；待验证记录为空。 |
| `identity_status` | 只允许 `pending`、`verified`。 |
| `identity_verified_at` | 最近一次身份验证成功时间；待验证记录为空。 |

新建接入源必须直接以 `verified` 保存。数据库建立部分唯一索引：已验证且账号 ID 非空的记录在 `(provider, cloud_account_id)` 上唯一。数据库检查约束保证 `verified` 必须同时具有账号 ID 和验证时间，`pending` 必须没有这两个值。

唯一索引有意禁止同一账号在同一项目创建多个接入源，也禁止跨项目重复归属，从数据层确保一个账号只有一个 CMDB 接入载体。

### 新建接入源

1. 共享服务校验基础字段、同步周期，并调用平台适配器严格校验凭证和配置。
2. 适配器使用提交的凭证和区域取得稳定账号 ID。
3. 身份识别失败时返回安全错误，不加密、不写接入源、不写成功审计。
4. 识别成功后才加密凭证，并在同一事务内写入已验证接入源和创建审计。
5. 服务可先查询冲突以返回清晰提示，但最终以唯一索引为准；并发冲突统一映射为 `409`，事务回滚且不泄露既有项目或接入源信息。

### 编辑与凭证替换

- 已验证接入源的云账号身份不可修改，`provider` 和 `cloud_account_id` 不作为普通编辑字段。
- 未提交凭证时保留原密文和已验证身份，只更新允许维护的非身份字段。
- 显式提交新凭证时，先完整校验并联网识别身份。识别结果必须等于当前 `cloud_account_id`；不同则返回 `409`，原凭证、配置、身份和时间全部保持不变。
- 新凭证校验、身份比对、加密、接入源更新和成功审计属于一次原子业务操作。

### 历史数据与“验证身份”

升级时不能假设历史凭证仍有效，也不能在数据库迁移中访问云 API，因此所有已有接入源统一迁移为：

- `identity_status = pending`；
- `cloud_account_id = NULL`；
- `identity_verified_at = NULL`。

待验证接入源及其历史资产和任务保持可查询，但普通编辑、启停、删除、连接测试、手工同步、重试和自动任务创建均返回 `409` 或从调度候选中排除。它只能执行专门的“验证身份”动作：

1. 操作者必须具有该项目的接入源管理权限，且项目必须处于启用状态；停用项目需要先由系统管理员重新启用。
2. 请求可以不提交凭证而验证现有密文，也可以提交一套完整新凭证以修复失效凭证；新凭证仍遵守平台严格校验。
3. 适配器取得账号 ID 后，共享服务在同一事务中执行唯一性确认、可选凭证替换、状态改为 `verified`、写入验证时间和审计。
4. 身份冲突、云调用失败或事务失败时，记录保持 `pending`，原密文不变。

新增项目接口 `POST /api/v1/projects/:id/sources/:sourceId/verify-identity`。请求中的 `credential` 可选且只存在于最短调用链；响应只返回更新后的脱敏接入源。

升级时遗留的 `queued` 或 `running` 任务不得在待验证接入源上继续采集。服务启动恢复流程将其安全收敛为 `failed`，清空资产变化统计，使用“接入源身份待验证，任务未执行”摘要；不会改变资产生命周期或成功时间。完成该收敛后，用户可在身份验证成功后重新发起任务。

## 删除保护

### 数据库约束

服务器、数据库和负载均衡三张资产表到 `projects`、`resource_sources` 的外键改为 `ON DELETE RESTRICT`。应用服务遗漏前置检查或出现并发竞争时，数据库仍不得级联删除资产。

同步任务保留现有历史处理方式，但接入源或项目存在 `queued`、`running` 任务时，业务删除必须拒绝。审计日志继续仅追加并独立长期保留。

### 服务事务

项目删除和接入源删除分别在同一事务中完成以下步骤：

1. 以固定顺序锁定目标项目、接入源父记录，防止同步入队和资产写入越过删除检查。
2. 查询三张资产表，只要任一表存在正常或已失联记录即拒绝。
3. 查询目标范围内的排队或运行任务，只要存在即拒绝。
4. 无依赖时写入包含最小非敏感快照的删除审计，再删除父对象并提交。

同步入队、重试创建、自动任务创建以及最终资产写入必须采用相同的父记录锁顺序。即使应用检查后发生外部并发，限制外键仍提供最后防线。业务依赖命中和数据库限制冲突统一映射为 `409` 中文错误，不产生成功删除审计；其他项目是否存在、资产数量及任务详情均不披露。

系统管理员只拥有授权层最高权限，不拥有破坏领域不变量的例外。必须先按正常同步生命周期清理资产并等待活动任务进入终态，才能删除项目或接入源。

## 同步结果与调度

### 确定性终态决策

从同步编排中抽出无副作用的结果决策函数。它接收平台应支持的类型集合、整体采集错误、逐类型结果和最终事务结果，先验证类型集合完整且没有重复，再按以下顺序决策：

| 条件 | 终态 | 资源与统计处理 |
| --- | --- | --- |
| 整体认证、权限或采集失败 | `failed` | 不改变资源，不保留资产变化统计。 |
| 没有任何成功类型，包括空结果、类型缺失或全部类型失败 | `failed` | 不改变资源；全部类型失败时只保留类型名、失败数 1 和安全分类。 |
| 至少一个成功类型且至少一个失败类型 | `partial_success` | 只处理成功类型；失败类型保持原资产状态。 |
| 所有预期类型均成功 | `success` | 处理所有类型。 |
| 最终资源事务提交失败 | `failed` | 回滚全部资源、统计、调度时间和审计，再以独立失败事务收敛。 |

不再使用“只要出现失败类型就是部分成功”的分支判断。成功类型数为零时绝不允许写入 `partial_success`、刷新最近同步时间或推进任何资源生命周期。

### 自动失败计划

- `success`、`partial_success` 延续既有规则：在最终成功事务中更新 `last_sync_at`，并将 `next_sync_at` 设为完成时间加同步周期。
- `scheduled` 任务进入 `failed` 时，在任务失败收敛事务中仅把 `next_sync_at` 推进到完成时间加同步周期；`last_sync_at` 保持不变。
- 普通 `manual` 任务和带 `previous_job_id` 的重试任务失败时，`last_sync_at`、`next_sync_at` 均保持不变。
- 自动失败后的计划推进只表示避免立即重复调度，不得出现在成功统计或成功审计中。

整体采集失败、全部类型失败和最终事务失败共用同一失败收敛入口，避免不同错误路径遗漏调度规则。终态、允许保留的安全类型失败信息、完成时间、自动失败计划和任务审计在一次失败事务中提交。

## PostgreSQL 17 显式迁移

### 运行模型

新增一次性 `cmdb-migrate` 管理命令和按版本组织的迁移文件。该命令使用 PostgreSQL 管理员凭证，获取数据库级迁移锁，在单个版本事务内检查前置结构、执行 DDL、记录版本；重复执行已完成版本是安全的。迁移失败时事务回滚并返回中文摘要，不启动应用，也不输出连接密码或 SQL 参数值。

应用使用的 `cmdb` 账号不授予 DDL 权限。服务启动不调用 `AutoMigrate`，只用只读查询确认 `schema_migrations` 处于程序要求的版本；版本缺失、落后或超前均拒绝启动，并提示运维执行匹配版本的迁移命令。

### 空库与已有数据卷

- 新建空库的初始化 SQL 直接创建最新表结构、限制外键、身份字段、检查约束、部分唯一索引和最新迁移版本。
- 旧数据卷首次升级若没有版本表，迁移命令先核验受支持旧结构的表和关键列指纹；完全匹配才登记旧基线并继续升级，未知或部分结构立即停止，禁止猜测性修改。
- 升级版本新增身份字段并把历史接入源设为 `pending`，替换三类资产外键；替换前检查孤儿记录，发现数据完整性问题即回滚并报告安全摘要。
- 迁移命令执行期间应用必须停止。升级文档提供备份、执行、版本核对、启动和回退到备份的演练步骤；不承诺对已提交 DDL 做自动降级迁移。

Docker 镜像包含应用、初始化管理员和迁移三个一次性/长期入口，但仍只有一个长期运行的 CMDB 服务，不新增微服务。Compose 和 README 明确区分 PostgreSQL 管理员迁移凭证与受限应用凭证，敏感值通过环境或标准输入传递，不放入命令行参数和日志。

## API、错误与审计

新增或稳定化以下错误类别，HTTP 层只返回中文安全消息：

- `400`：平台凭证字段或非敏感配置不合法；
- `409`：账号已接入、替换凭证指向不同账号、接入源待验证、存在资产或活动任务而不能删除、同源任务冲突；
- `502`：调用云平台识别身份失败，包括安全分类后的认证、权限、网络或超时问题；
- `500`：数据库事务或内部依赖失败，不回显 SQL 和云 SDK 原始错误。

接入源创建、身份验证、凭证替换、删除结果和同步终态继续记录审计。失败操作不得产生成功审计；需要记录的失败只保存动作、公开对象标识、平台、结果分类和时间，不保存账号凭证、完整密文、原始响应、请求正文或堆栈。

## 前端交互

统一“云同步管理”页面扩展接入源身份状态：

- 接入源列表显示“已验证”或“待验证”中文状态，不显示云账号 ID，以免扩大账号标识披露面。
- 待验证记录保留历史信息，只提供“验证身份”；编辑、启停、删除、连接测试、立即同步和相关任务重试均禁用，并解释验证完成后才能恢复操作。
- 验证身份弹窗默认使用现有安全凭证，可选择输入一套完整新凭证；提交期间清空旧错误并禁止重复操作，结束后立即清理页面中的凭证对象。
- 新建和显式替换凭证时显示“正在验证云账号身份”，等待后端完成后再显示成功；后端拒绝后重新查询服务端事实，不保留伪成功状态。
- 账号冲突、身份不一致、待验证和删除依赖冲突显示稳定中文说明，不显示其他项目、接入源、账号 ID、内部 ID 或云端原始错误。

后端始终执行相同约束；按钮禁用不承担安全职责。普通项目成员仍只能查看脱敏状态，不能执行验证身份。

## 代码职责与预期改动

- `backend/internal/aliyun`、`backend/internal/aws`：各自实现严格字段校验、稳定账号识别和模拟云 API 测试。
- `backend/internal/resource`：定义平台适配契约，负责身份状态、唯一归属事务、待验证运行门禁、删除保护、同步终态决策和自动失败调度。
- `backend/internal/project`：项目删除在资源依赖检查和父记录锁保护下执行。
- `backend/internal/platform/database`、`backend/cmd/migrate`、`backend/database`：版本检查、一次性迁移入口、空库最新结构和已有数据卷升级。
- `backend/internal/platform/httpserver`：装配平台适配器并将稳定领域错误映射为 HTTP 响应。
- `frontend/src/modules/resource`：显示身份状态、提供验证身份流程、禁用待验证操作并清理凭证瞬时状态。
- `frontend/src/modules/project`：先修复基线已有的两个项目表单回调类型错误，使生产构建恢复为可验证基线；不改变项目表单业务行为。
- `docs/project`、根 `README.md`、部署配置：同步长期规范、验收场景、实现证据和升级操作。

若实施中发现以上职责需要跨越新的服务边界、引入新平台或改变已确认业务语义，必须停止并重新确认设计。

## 测试驱动实施与验收

### 后端失败测试

实现前至少覆盖：

- 两个平台凭证必填、未知字段、空值和配置非空/敏感键拒绝；
- 模拟账号识别成功、认证失败、权限不足、超时和网络失败，且失败不落库；
- 同账号同项目、跨项目和并发创建冲突；替换凭证身份相同成功、身份不同原子拒绝；
- 历史迁移为 `pending`，待验证门禁、使用原凭证/新凭证验证、冲突回滚和遗留任务安全收敛；
- 三类资产分别阻止项目和接入源删除，活动任务阻止删除，无依赖删除成功且审计一致；
- 删除检查与并发同步/资产写入竞争不能造成级联资产丢失；
- 全成功、部分成功、全部类型失败、空结果、整体失败、类型集合异常和最终事务失败的确定性状态；
- 自动失败推进下次计划，手工和重试失败保持计划，最近成功时间不被失败刷新。

### PostgreSQL 17 集成测试

关键数据库不变量不能只由 SQLite 单元测试证明。集成测试使用 PostgreSQL 17 临时实例验证：

- 部分唯一索引在并发事务下拒绝重复账号；
- 三类限制外键阻止父对象删除，事务锁让删除与同步竞争得到确定结果；
- 旧结构识别、迁移成功、重复执行、未知结构拒绝、孤儿数据拒绝和版本检查；
- 应用账号不能执行 DDL，但能读取版本并完成正常业务操作。

交付前必须以新输出重新验证：

## 提交与集成策略

- 所有修改在 `codex/p0-safety-iteration` 隔离工作区完成。
- 按可独立验证的逻辑拆分提交：基线类型修复、迁移基础、平台身份、接入源流程、删除保护、同步状态、前端流程、产品文档与验收状态。

- 完成后将工作分支纳入最新 `main`，执行全套验收，再通过本地合并或 Pull Request 合入 `main`；合并完成前不视为交付完成。
