# CMDB 第一阶段稳定性优化设计

## 目标

在不删除现有业务模块、不扩展新业务能力的前提下，修复阻断核心功能使用的权限、身份、安全、路由、前端响应解析和数据一致性问题，并建立覆盖这些修复的最小自动化测试基础。

## 范围

本阶段包含：

1. 统一默认管理员与路由授权规则，确保 `super_admin` 拥有全部 `cmdb_admin` 权限。
2. 前端保存并使用登录接口返回的真实用户和角色；菜单、页面入口及写操作按钮按权限显示。
3. 统一前端 API 响应类型与解包规则，修复采集策略、采集历史、配置快照和 Diff 页面取数错误。
4. 修复采集策略编辑时 `target_config` 没有正确进入提交数据的问题。
5. 审计日志正确读取 JWT 中的用户身份，并对密码类请求体脱敏。
6. 变更流转使用服务端认证身份记录操作者，不接受客户端伪造操作人。
7. 修复 CSV 导入时资产来源被覆盖、静态路由被参数路由抢占、初始化关系规则唯一键冲突以及 JWT 过期配置未生效的问题。
8. 增加能够防止上述问题回归的最小单元测试。

本阶段不包含：自动发现手动执行、采集器补全、真实容量监控、真正配置回滚、Webhook 鉴权、Compose 前端部署或全项目测试补齐。这些进入第二、第三阶段。

## 设计

### 1. 角色与前端权限

后端将角色判断集中到单一匹配函数。`super_admin` 是最高权限角色，在所有 `RequireRole` 检查中自动通过；其他角色保持现有授权范围。用户模型的默认管理员角色继续使用 `super_admin`，避免迁移已有数据。

登录成功后，前端认证状态保存 token、用户 ID、用户名、显示名和角色列表。页面刷新时从本地持久化状态恢复。侧栏菜单和写操作使用相同的角色判断规则：`super_admin` 拥有所有权限，`cmdb_admin` 拥有管理权限，`asset_mgr` 仅拥有现有资产和变更操作权限。后端始终是最终授权边界，前端控制只用于用户体验。

### 2. API 响应与页面取数

保留后端 `{code, message, data}` 响应格式。前端请求封装继续返回完整业务响应，不进行第二次隐式解包；各 API 定义显式描述 `data` 中的负载结构。采集策略、采集历史、快照列表和 Diff 页面统一从 `response.data` 读取。

采集策略表单使用独立的 JSON 文本编辑状态。提交前解析为对象写入 `target_config`；非法 JSON 阻止提交并显示错误。编辑已有策略时，将对象稳定格式化到文本框。

### 3. 认证身份与审计

认证中间件统一写入 `user_id`、`username` 和 `roles` 上下文键。业务处理通过共享身份读取函数获取操作者，不从请求体读取可信身份字段。

审计中间件从 `user_id` 获取身份。对于登录、修改密码和重置密码请求，不持久化原始请求体；审计记录保留路径、方法、状态、耗时和来源 IP。非敏感请求仍按现有行为记录，但限制请求体最大采集长度，避免异常大载荷进入审计表。

变更提交、审批、驳回、执行、完成、失败和回滚的操作者由认证上下文决定。缺少有效身份时返回未授权，不执行状态变更。

### 4. 路由与数据一致性

所有静态子路径在 `/:id` 参数路由之前注册，包括 CI 导入导出和快照 Diff，保证 Gin 使用明确处理器。

CSV 导入明确使用模型已有的标准来源值 `import`。实例服务只在来源为空时补默认值 `manual`，不得覆盖调用方已经设置的合法来源。测试断言导入记录经过服务创建后仍保留 `import`。

种子关系规则的唯一性与业务含义对齐：允许同名关系用于不同的源类型和目标类型，以 `(name, source_type_id, target_type_id)` 作为唯一维度；迁移和模型约束保持一致。

JWT 签发过期时间使用配置的 `ExpireHour`；配置无效时在加载阶段回退到明确的安全默认值 24 小时。

### 5. 测试策略

后端使用 Go 标准测试工具，优先测试不依赖真实 MySQL 的纯函数和 HTTP 中间件：

- `super_admin`、`cmdb_admin`、`asset_mgr` 的角色判断。
- JWT 配置过期时间和认证上下文写入。
- 敏感路径审计脱敏。
- 静态路由匹配到正确处理器。
- CSV 来源规范化函数。
- 关系规则唯一索引的模型/迁移约束。

前端采用 Vitest；若项目尚未配置测试框架，将添加最小 Vitest 配置，只测试提取出的纯函数和认证状态：

- API 分页负载和 Diff 负载解包。
- 策略配置 JSON 的解析与错误处理。
- 不同角色的菜单/操作权限判断。
- 登录状态的持久化与恢复。

每项修复遵循先失败测试、再最小实现、最后全量构建验证的顺序。

## 兼容与迁移

- 不删除 API，不改变后端统一响应外形。
- 不更改已有角色数据；只补充 `super_admin` 的权限继承语义。
- 关系唯一约束变更必须兼容已有数据，并在添加约束前检查重复项。
- 前端本地保存的旧 token 若缺少用户资料，视为需要重新登录，不猜测管理员身份。
- 不修改未提交的关系和仪表盘业务逻辑；如必须触及同一文件，只做最小局部合并并单独说明。

## 验收标准

1. 默认管理员登录后可以访问并执行所有管理操作。
2. 普通用户、资产管理员和 CMDB 管理员的读写权限符合后端规则，直接调用越权接口仍被拒绝。
3. 采集策略、历史、快照和 Diff 页面能正确展示后端响应；非法策略 JSON 无法提交。
4. 审计日志不会保存登录密码或新密码，并能关联正确用户。
5. 客户端不能伪造变更操作者。
6. CSV 导入来源、关系规则初始化、静态路由和 JWT 过期配置均有回归测试。
7. 后端测试、前端测试和前端生产构建全部通过；若环境缺少 Go 工具链，需明确报告未验证项，不得声称后端测试通过。
