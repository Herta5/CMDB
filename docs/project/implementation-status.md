# CMDB 实现状态

## 用途与基线

本文以提交 `9c7a75c`（完整提交 `9c7a75c0d4e19ae505e2d2ceca712b9918635b9a`）为变更前基线，并纳入与本文同提交的最终安全修复，用于追溯当前交付能力和后续差距；它不改变 [项目规范入口](README.md) 及其链接规范中的任何长期要求。状态仅使用“已实现”“部分实现”“待实现”：已实现表示基线及本轮代码和测试已覆盖该能力，部分实现表示已有可用实现但未满足全部规范边界，待实现表示基线未提供该能力。

后续功能提交必须同时更新受影响行的状态、证据和差距。证据均为基线中的真实代码或测试路径；测试使用模拟响应或隔离数据库，不连接真实云账号。

本轮增量证据：`backend/internal/platform/database/postgres_integration_test.go` 以 PostgreSQL 17 的 DDL 事件与非事务序列证明非空历史配置在任何结构变更前拒绝，且原数据不变、空对象升级可用；`backend/internal/resource/http.go`、`backend/internal/platform/httpserver/integration_test.go` 证明 Probe 认证与权限分类独立、创建和编辑内部故障安全返回 500 并回滚来源及审计；`frontend/src/modules/resource/store.test.ts` 与 `frontend/src/app-flow.test.ts` 用真实状态层和组件交互、可控传输证明旧验证刷新错误、创建/编辑刷新与弹窗迟到回调均不能接管新项目或新输入。 第二轮补充同项目轮询不作废创建/编辑提交、关闭验证弹窗后同源重开与旧请求隔离，以及同步/连接来源读取内部故障 500 和防枚举 404 的真实行为回归。
