# CMDB 云资源同步规范

## 文档职责

本文档定义接入源配置、连接测试、同步任务、资源生命周期和同步结果的统一契约。接入源、任务和资产的归属、身份及字段语义由 [domain-model.md](domain-model.md) 定义；项目级授权规则由 [security.md](security.md) 定义。任何云平台采集器都必须接入同一套同步核心规则，不得在阿里云或 AWS 模块中复制实现。

## 接入源与连接测试

- 接入源必须归属于唯一业务项目，并记录云平台、名称、区域、加密凭证、非敏感配置、启用状态、同步周期、最近同步时间和下次同步时间。阿里云与 AWS 是独立平台模块；一个云账号或云租户不得借由不同接入源跨项目重复接入。
- 凭证必须加密存储和脱敏展示。非敏感配置仅用于保存区域之外的平台采集选项；它不得承载密码、令牌、AccessKey、主加密密钥或完整密文。
- 新建接入源默认启用，默认同步周期为 60 分钟；同步周期必须为 5 至 10080 分钟的整数。停用接入源后不得再由自动调度发起同步。
- 连接测试必须使用轻量探测，仅验证凭证认证、只读权限、网络和各资源类型 API 的可达性，并返回可达与不可达的资源类型。它不得遍历或返回完整资源快照。
- 连接测试不是同步：不得写入资源、不得创建同步任务、不得更新最近或下次同步时间、不得执行失联或物理删除判定，也不得推进任何资产生命周期。连接测试结果必须记录审计，但审计仅保存安全结果摘要。

## 触发、调度与并发

- 有权限的用户手工发起同步时，服务必须先持久化并返回状态为“排队”（`queued`）的任务；资源采集在后台执行，接口不得等待完整采集结束。
- 自动调度只处理已启用且下次同步时间已到的接入源。一次成功或部分成功的同步完成后，必须按该接入源的同步周期更新最近同步时间和下次同步时间。
- 同一接入源的自动同步、手工同步和重试必须互斥。接入源已有排队或运行任务时，不得再为该接入源创建新任务；不同接入源可以并行执行。
- 手工重试属于手工触发的一种来源，但必须通过新建任务与原任务关联，不能改写原任务记录。

## 任务状态与结果

同步任务的状态只允许按以下语义流转：

- “排队”（`queued`）：请求已受理并已持久化，尚未由工作器开始执行。
- “运行中”（`running`）：工作器已开始处理接入源，尚未写入终态。
- “成功”（`success`）：全部资源类型都成功采集并完成持久化处理。
- “部分成功”（`partial_success`）：至少一个资源类型成功处理，且至少一个资源类型采集失败；成功类型的变更有效，失败类型保持同步前状态。
- “失败”（`failed`）：认证失败、整体采集失败、凭证无法使用，或资源处理事务未能提交。失败任务不得保留未提交的资源变化或统计。

任务只能由 `queued` 进入 `running`，并由 `running` 进入 `success`、`partial_success` 或 `failed`。终态任务不可改写为其他终态；重试必须新建任务。任务必须记录触发方式、开始和完成时间、按类型统计、可选的原任务标识及安全错误摘要。

## 类型级处理与统计

- 每次同步必须按资源类型独立处理。每个已尝试类型都必须记录新增、更新、恢复、失联、删除和失败数量；成功类型的失败数为 0，采集失败类型的其他数量为 0、失败数为 1。
- 某一类型采集失败时，不得对该类型写入资源，不得将该类型资源标记失联，不得恢复或删除该类型资源；其他已成功类型仍可按本规范处理，任务终态为 `partial_success`。
- 认证失败、整体采集失败或任务未执行时，不得改变任何资源的资产状态、失联时间或物理存储，也不得以失败结果推进删除。
- 任务状态和统计不得因单类资源失败而丢弃成功类型的处理结果；反之，资源写入事务失败时不得遗留无法与任务统计对应的部分资源变更。

## 资源生命周期

资源以“接入源 + 资源类型 + 云端唯一 ID”作为唯一身份。以下判定只适用于该接入源、该资源类型的一次成功采集；云端状态和 CMDB 资产状态仍是 [domain-model.md](domain-model.md#状态与时间语义) 所定义的两个独立维度。

- **新增**：成功采集到库中不存在的资源身份时，创建资源，写入首次发现时间和最近发现时间，并将资产状态置为“正常”。
- **幂等刷新**：再次发现同一资源且稳定业务字段、原始属性和端点均未变化时，只刷新最近发现时间；不得更新业务更新时间、增加更新统计或产生无意义审计。易变观测属性变化时，只更新观测快照和最近发现时间，同样不得计为业务更新。
- **真实更新**：同一资源的稳定业务字段、受管原始属性或端点发生变化时，更新原记录，计入更新统计并留下更新审计；云平台原始属性只能由同步模块维护。
- **失联**：一次成功采集未返回原本状态为“正常”的同类型资源时，将其标记为“已失联”，写入失联开始时间，计入失联统计并留下审计。不得以其他资源类型、失败采集或定时器的结果做此判定。
- **恢复**：状态为“已失联”的资源在同类型成功采集中再次出现时，必须恢复同一记录为“正常”并清空失联开始时间，计入恢复统计并留下审计，不得新建重复资源。
- **物理删除**：资源已连续失联满 24 小时后，必须由发生在该时长届满之后的同类型成功采集再次确认其仍未出现，才允许物理删除。删除必须计入当前任务的删除统计并留下独立审计。物理删除不得只由失联开始时间、定时器、认证失败或任何失败采集触发。

## 事务与一致性边界

- 对成功处理的资源类型，资源新增、更新、恢复、失联和删除，类型统计，任务终态，最近及下次同步时间，以及相应审计必须在一致的事务边界内提交。事务失败时必须回滚其中所有资源变化、统计、调度时间和审计。
- 资源处理事务失败后，任务必须收敛为 `failed`，并只记录可安全公开的失败摘要；不得把未生效的资源统计作为任务结果保存。
- 审计必须与其所描述的接入源、任务或资源变化一致；资源物理删除后，审计日志仍须长期保留，供历史追溯。

## 重试与服务重启恢复

- 只有状态为 `failed` 或 `partial_success` 的任务可以重试。重试必须创建新的 `queued` 任务，并记录原任务标识；原任务的状态、统计、时间和摘要必须保持不变。
- 服务启动时必须恢复仍为 `queued` 的任务，使其重新进入正常执行流程；服务异常中断遗留的 `running` 任务必须收敛为 `failed`，并使用“服务重启导致任务中断，可重新执行”这一类安全摘要。中断任务可由用户按重试规则重新发起。
- 恢复和重试仍遵守同一接入源互斥、项目归属、授权和采集器边界；不得因恢复而绕过启停、凭证保护或生命周期规则。

## 错误摘要与敏感信息

- 任务日志、错误摘要、连接测试结果和审计只允许保存中文安全摘要或有限的业务错误分类，例如“凭证认证失败”“云账号权限不足”或“网络连接失败”。
- 不得保存或返回云平台原始错误响应、请求响应正文、密码、令牌、AccessKey、主加密密钥、完整凭证或完整密文。任何诊断信息都必须先完成脱敏和分类收敛后才能进入任务或审计记录。
