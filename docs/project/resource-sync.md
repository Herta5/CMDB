# CMDB 云资源同步规范

## 文档职责

本文档定义接入源配置、连接测试、同步任务、资源生命周期和同步结果的统一契约。接入源、任务和资产的归属、身份及字段语义由 [domain-model.md](domain-model.md) 定义；项目级授权规则由 [security.md](security.md) 定义。任何云平台采集器都必须接入同一套同步核心规则，不得在阿里云或 AWS 模块中复制实现。

## 接入源与连接测试

- 接入源必须归属于唯一业务项目，并记录云平台、名称、区域、加密凭证、非敏感配置、启用状态、同步周期、最近同步时间、下次同步时间，以及 [接入源身份](domain-model.md#接入源身份) 所定义的非空稳定账号标识和验证时间。阿里云与 AWS 是独立平台模块；一个云账号或云租户不得借由不同接入源在同一项目重复创建或跨项目重复接入。
- 凭证必须加密存储和脱敏展示。非敏感配置仅用于保存区域之外的平台采集选项；它不得承载密码、令牌、AccessKey、主加密密钥或完整密文。
- 平台适配器必须在加密和持久化前严格校验字段。阿里云凭证只接受非空字符串 `access_key_id`、`access_key_secret`；AWS 只接受非空字符串 `access_key_id`、`secret_access_key` 和可选的 `session_token`。缺少必填项、空白值、非字符串值、重复字段、未知字段、非对象或尾随 JSON 均须以稳定中文参数错误拒绝。首期 `config` 只允许缺失值或空对象，任意业务字段或递归命中的敏感键都必须拒绝。
- 新建接入源默认启用，默认同步周期为 60 分钟；同步周期必须为 5 至 10080 分钟的整数。停用接入源只阻止未来自动任务创建，不得取消已受理的排队或运行任务。
- 新建接入源必须在保存前使用提交凭证执行轻量身份识别：阿里云通过 STS `GetCallerIdentity` 获取账号 ID，AWS 通过 STS `GetCallerIdentity` 获取 12 位 Account ID。两平台身份请求必须显式或由受回归测试保护的 SDK 默认值使用 HTTPS，不得回退到明文 HTTP。无法识别、返回值不合法或发现同平台账号已经接入时，不得加密或持久化任何接入源变化，也不得写成功审计。
- 阿里云和 AWS 的身份识别、连接探测及完整同步所调用的全部云 API，包括资源列表、后续分页、实例详情、监听器、计算规格、云盘和网络信息，必须使用 HTTPS 并校验证书，不得回退或重定向到 HTTP。平台模块必须对所有当前产品提供进程内协议回归测试；测试只检查虚构请求的最终出站协议，不连接真实云账号。
- 普通编辑不得修改平台或稳定账号身份；未提交新凭证时保留原密文和身份。显式替换完整凭证时必须先联网识别，并且只允许识别为原账号；不同账号、云调用失败或事务失败时，原凭证、配置、身份和验证时间必须全部保持不变。
- 创建与编辑只把有限的基础字段、周期、凭证和配置领域错误分类为 `400 SOURCE_INVALID_INPUT`；账号归属冲突保持稳定 `409`。云身份识别的认证、权限或网络故障统一使用 `502 CLOUD_IDENTITY_UNAVAILABLE`，但分别返回“检查凭证”“检查身份查询授权”或“检查服务端网络”的中文安全提示。未知数据库、事务、审计、加密或适配器依赖故障统一返回 `500 SOURCE_SERVICE_UNAVAILABLE` 和中文安全摘要，不能当成用户参数错误；所有失败保持业务与审计原子回滚。
- 连接测试必须使用轻量探测，仅验证凭证认证、只读权限、网络和各资源类型 API 的可达性，并返回可达与不可达的资源类型。服务器类型的探测必须覆盖完整同步依赖的补充只读 API：阿里云 ECS 同时探测实例与云盘列表，AWS EC2 同时探测实例、实例类型详情与 EBS 列表。数据库类型的探测必须覆盖规格补充权限：阿里云在列表存在实例时只读取首个 RDS 实例详情；AWS 复用 EC2 实例类型详情的最小权限探测。负载均衡探测只调用阿里云 SLB、ALB、NLB、GWLB 的四个产品列表 API、AWS Classic 列表和一次 AWS ELBv2 列表；每项只请求最小页面或首个实例，不得遍历分页、读取监听器、解析域名、写入资源或返回完整资源快照。
- 连接探测的权限不足保持 `403 SOURCE_PERMISSION_DENIED`，认证失败保持 `502 SOURCE_AUTHENTICATION_FAILED`，网络等其他探测失败为 `502 SOURCE_CONNECTION_FAILED`；这些探测分类与创建或替换凭证时的云账号身份识别错误分离，只返回安全中文说明，不回显云原始错误。
- 手工同步和连接测试在读取接入源时，只有真实不存在或不属于路径项目的来源返回统一 `404 SOURCE_NOT_FOUND`；数据库等内部读取故障返回安全 `500 SOURCE_SERVICE_UNAVAILABLE`。读取失败不得进入采集或探测，不创建任务，不改变资源、凭证、同步计划或审计。
- 连接测试不是同步：不得写入资源、不得创建同步任务、不得更新最近或下次同步时间、不得执行失联或物理删除判定，也不得推进任何资产生命周期。连接测试结果必须记录审计，但审计仅保存安全结果摘要。

## 触发、调度与并发

- 有权限的用户手工发起同步时，服务必须先持久化并返回状态为“排队”（`queued`）的任务；资源采集在后台执行，接口不得等待完整采集结束。
- 自动调度只处理已启用且下次同步时间已到的接入源。一次成功或部分成功的同步完成后，必须按该接入源的同步周期更新最近同步时间和下次同步时间。
- 自动触发（`scheduled`）的任务失败时，必须将下次自动执行时间推进到任务完成时间加配置周期，避免无间隔重复发起。手工触发（`manual`）或带有原任务标识的重试任务失败时，不得改变既有自动计划。
- 同一接入源的自动同步、手工同步和重试必须互斥。接入源已有排队或运行任务时，不得再为该接入源创建新任务；不同接入源可以并行执行。
- 触发方式（`trigger`）的稳定值仅为自动的 `scheduled` 与手工的 `manual`。重试使用 `manual`，并通过原任务标识（`previous_job_id`）与普通手工任务区分；它必须通过新建任务关联原任务，不能改写原任务记录。

## 任务状态与结果

同步任务的状态只允许按以下语义流转：

- “排队”（`queued`）：请求已受理并已持久化，尚未由工作器开始执行。
- “运行中”（`running`）：工作器已开始处理接入源，尚未写入终态。
- “成功”（`success`）：全部资源类型都成功采集并完成持久化处理。
- “部分成功”（`partial_success`）：至少一个资源类型采集成功，且至少一个资源类型采集失败；全部成功类型的变更与全部类型统计在最终事务中一并提交后才生效，失败类型保持同步前状态。
- “失败”（`failed`）：认证失败、整体采集失败、全部资源类型分别采集失败、凭证无法使用，或最终资源处理事务未能提交。即使采集器 `Collect` 整体返回 `nil` 错误，只要没有任何类型成功且全部类型失败，也必须判为 `failed`。失败任务不得保留资源变化或资产变化统计；全部类型失败时可保留安全的逐类型失败信息，具体口径见下节。

平台声明的预期资源类型集合必须非空且无重复，采集结果必须完整、无重复并且不包含额外类型；空结果、缺少类型、重复类型或额外类型均属于失败，不得保留其中的局部成功快照。任务只能由 `queued` 进入 `running`，并由 `running` 进入 `success`、`partial_success` 或 `failed`。终态任务不可改写为其他终态；重试必须新建任务。任务必须记录触发方式、开始和完成时间、按类型统计、可选的原任务标识及安全错误摘要。

## 类型级处理与统计

- 每次同步必须按资源类型独立处理。成功或部分成功任务的每个已尝试类型都必须记录新增、更新、恢复、失联、删除和失败数量；成功类型的失败数为 0，采集失败类型的其他数量为 0、失败数为 1。
- 某一类型采集失败时，不得对该类型写入资源，不得将该类型资源标记失联，不得恢复或删除该类型资源；权限不足、补充 API 失败或其他单类型错误必须记录在对应类型结果中并继续采集其他类型，不能升级为采集器整体失败。只有凭证认证失效等接入源整体不可用错误才允许整体终止；至少一个其他类型成功且最终事务提交成功时，任务终态为 `partial_success`。
- 服务器类型只有在实例列表、计算规格和已挂载云盘明细全部成功采集后才算成功。阿里云 `DescribeDisks` 必须使用合法的用途筛选值并只接收状态为 `In_use` 的云盘，AWS 只接收 attachment 状态为 `attached` 的 EBS；两平台均须排除实例规格附带、没有稳定云盘 ID 的临时本地盘。阿里云 `DescribeDisks` 或 AWS `DescribeInstanceTypes`、`DescribeVolumes` 失败，任一实例缺少实例类型、有效 vCPU 或内存信息，AWS 存在已挂载 EBS 但缺少根设备名，或者已挂载云盘缺少稳定 ID、系统盘/数据盘标识、磁盘类型、有效容量、设备名或加密状态时，整个 ECS 或 EC2 类型必须失败，不得以空值或不完整磁盘数组覆盖最近一次有效快照。
- 数据库类型必须保存实例规格、存储类型和云平台提供的已分配存储容量，并在可靠可得时保存 vCPU 与内存。阿里云完整同步必须逐实例读取 `DescribeDBInstanceAttribute` 规格详情；AWS 必须保存 `DBInstanceClass`、`StorageType` 和 `AllocatedStorage`，并通过去除 `db.` 前缀后的 EC2 实例类型详情补充固定规格的 CPU 与内存。Serverless 或云平台没有对应固定实例类型时 CPU、内存保持为空；规格补充 API 失败或阿里云实例详情缺失时整个 RDS 类型失败并保留旧快照，不得用空值覆盖。RDS 只保存存储类型与总容量，不构造逐盘明细。
- 全部类型分别采集失败时，任务必须为 `failed`，可保留资源类型、失败数 1 和中文安全失败分类，不得产生新增、更新、恢复、失联或删除等资产变化统计；不得刷新最近同步时间、最近发现时间或任何生命周期时间。仅自动失败的下次执行时间按“触发、调度与并发”推进，该安排不代表采集成功。
- 认证失败、整体采集失败、全部类型失败或任务未执行时，不得改变任何资源的资产状态、失联时间或物理存储，也不得以失败结果推进删除；失败及未执行不得推进最近同步时间的成功语义。
- 任务状态和统计不得因单类资源失败而丢弃成功类型的处理结果；反之，最终资源处理事务失败时不得遗留无法与任务统计对应的部分资源变更。

### 负载均衡产品采集

- 完整同步只覆盖接入源配置的单个 Region，并对列表结果读取全部分页。阿里云分别采集 SLB、ALB、NLB、GWLB 四个产品；AWS 单独采集 Classic Load Balancer 为 `clb`，ELBv2 的完整列表只读取一次后按 `alb`、`nlb`、`gwlb` 分组。阿里云预期顺序为 `ecs`、`rds`、`slb`、`alb`、`nlb`、`gwlb`，AWS 为 `ec2`、`rds`、`clb`、`alb`、`nlb`、`gwlb`。
- 阿里云 SLB、ALB、NLB、GWLB 以及 AWS Classic Load Balancer、ELBv2 的列表、分页和监听器请求均必须使用 HTTPS；某个产品仍兼容 HTTP 不构成降级理由，协议不符合要求时该产品不得被视为成功采集。
- 阿里云任一产品的列表、分页或监听器读取失败只使该产品类型失败；AWS 单一分组的监听器失败只使对应 `alb`、`nlb` 或 `gwlb` 失败。AWS ELBv2 列表失败或返回未知产品类型时，`alb`、`nlb`、`gwlb` 必须全部安全失败；认证失败仍按接入源整体终止。失败类型没有新快照，且不得推进该类型生命周期。
- 负载均衡只保存既有基础字段、网络类型和访问端点，不采集或结构化 Target Group、Server Group、后端服务器、健康检查、转发规则、证书、TLS 策略、监控或跨 Region 自动发现。旧通用 `elb` 不得出现在预期类型、采集结果、统计、页面查询或审计标签中。

## 资源生命周期

资源以“接入源 + 资源类型 + 云端唯一 ID”作为唯一身份。以下判定只适用于该接入源、该资源类型的一次成功采集；云端状态和 CMDB 资产状态仍是 [domain-model.md](domain-model.md#状态与时间语义) 所定义的两个独立维度。

- **新增**：成功采集到库中不存在的资源身份时，创建资源，写入首次发现时间和最近发现时间，并将资产状态置为“正常”。
- **幂等刷新**：再次发现同一资源且稳定业务字段、原始属性和端点均未变化时，只刷新最近发现时间；不得更新业务更新时间、增加更新统计或产生无意义审计。易变观测属性变化时，只更新观测快照和最近发现时间，同样不得计为业务更新。
- **真实更新**：同一资源的稳定业务字段、受管原始属性或端点发生变化时，更新原记录，计入更新统计；云平台原始属性只能由同步模块维护。
- **失联**：一次成功采集未返回原本状态为“正常”的同类型资源时，将其标记为“已失联”，写入失联开始时间，计入失联统计。不得以其他资源类型、失败采集或定时器的结果做此判定。
- **恢复**：状态为“已失联”的资源在同类型成功采集中再次出现时，必须恢复同一记录为“正常”并清空失联开始时间，计入恢复统计，不得新建重复资源。
- **物理删除**：资源已连续失联满 24 小时后，必须由发生在该时长届满之后的同类型成功采集再次确认其仍未出现，才允许物理删除。删除必须计入当前任务的删除统计。物理删除不得只由失联开始时间、定时器、认证失败或任何失败采集触发。
- 上述五种真实变化不为每项资源分别添加审计记录，而是按动作、资源类型和稳定排序的云端唯一 ID 计入本次同步唯一的 `source.synced` 聚合审计详情；幂等刷新和仅易变观测属性刷新不进入变化清单。

## 事务与一致性边界

- 采集完成后，必须以一个最终事务一次性提交全部成功类型的资源新增、更新、恢复、失联和删除、全部资源类型统计、任务终态、最近及下次同步时间，以及唯一一条 `source.synced` 聚合审计。该审计同时写入完整变化清单，按动作、资源类型和稳定排序的全部云端唯一 ID 归组；`partial_success` 与 `success` 都只能由该最终事务提交；不得按资源类型分别提交。
- 最终事务失败时，必须回滚其中全部资源变化、统计、调度时间和聚合审计详情；随后另起事务将任务收敛为 `failed` 并记录可安全公开的失败摘要及全新的空变化集合。该失败任务不得保留统计、已回滚的资源 ID 或任何成功类型的资源变更。
- 每次同步只追加一条 `source.synced` 审计，且审计必须与其所描述的接入源、任务和变化详情一致；资源物理删除后，聚合详情仍须长期保留云端唯一 ID 供历史追溯。人工交付时的一次性历史清空不构成后续审计删除规则，新审计仍须仅追加、长期保留。

## 重试与服务重启恢复

- 只有状态为 `failed` 或 `partial_success` 的任务可以重试。重试必须创建新的 `queued` 任务，并记录原任务标识；每次重试都必须重新完整采集接入源已配置的全部资源类型，不得只采集原任务失败的类型；原任务的状态、统计、时间和摘要必须保持不变。
- 服务启动时必须恢复仍为 `queued` 的任务，使其重新进入正常执行流程；服务异常中断遗留的 `running` 任务必须收敛为 `failed`，并使用“服务重启导致任务中断，可重新执行”这一类安全摘要。中断任务可由用户按重试规则重新发起。
- 恢复和重试仍遵守同一接入源互斥、项目归属、授权和采集器边界；重启恢复已受理的 `queued` 任务不受随后停用接入源影响。未来自动任务创建仍必须遵守启用状态，恢复和重试不得绕过凭证保护或生命周期规则。

## 错误摘要与敏感信息

- 任务日志、错误摘要、连接测试结果和审计只允许保存中文安全摘要或有限的业务错误分类，例如“凭证认证失败”“云账号权限不足”或“网络连接失败”。
- 不得保存或返回云平台原始错误响应、请求响应正文、密码、令牌、AccessKey、主加密密钥、完整凭证或完整密文。任何诊断信息都必须先完成脱敏和分类收敛后才能进入任务或审计记录。

## 同步运行资源与退出边界

- 单实例 CMDB 中的自动、手工、重试和启动恢复必须共享同一全局执行名额；默认最多同时执行 4 个任务，可通过 `CMDB_SYNC_MAX_CONCURRENT` 配置为 1 至 64。同源互斥覆盖持久化的 `queued` 与 `running` 状态，内存锁释放不能绕过遗留活动任务。
- 超出并发限额的已受理任务必须保持持久化 `queued`，不得提前采集或消耗执行时间预算。获得名额后才更新开始时间并进入 `running`；执行预算覆盖前置数据库读取、采集和最终事务，默认 900 秒，通过 `CMDB_SYNC_TIMEOUT_SECONDS` 配置为 1 至 86400 秒。
- 超时或关闭取消必须传递到云请求与响应体读取。AWS 使用 SDK context，阿里云统一 HTTPS transport 绑定任务 context，阿里云每次 HTTP 请求另有 30 秒上限。适配器必须协作响应取消，禁止通过放弃仍在运行的采集 goroutine 来提前释放并发名额。
- 超时、取消或采集异常后，任何迟到快照均不得写入资产；正常资产和已失联满 24 小时资产均保持原状。超时摘要为“同步执行超时，可重新执行”，关闭中断摘要为“同步执行已中断，可重新执行”，异常摘要为“同步执行异常，可重新执行”。失败统计为空，最近成功同步时间不变；自动任务的下次计划仍按失败规则推进。
- 获得名额后的前置读写超时、采集超时、最终事务失败与异常必须尝试独立失败收敛，最小审计身份和可信请求关联可保留，原 HTTP 请求和凭证不得保留。失败收敛使用独立的总计 10 秒预算，原执行 context 被取消不能阻止失败状态与唯一失败审计的原子提交；若数据库仍不可用，必须输出安全诊断并保留可恢复记录，不得伪称已落库。
- 服务关闭时停止自动扫描和新任务受理，停止领取等待任务，取消正在执行的采集并尝试失败收敛。尚未开始的任务保留 `queued`，下次启动在同一并发限制下恢复；来源随后停用不取消既有任务。HTTP 与工作器退出等待最多 15 秒，Compose 给予 30 秒退出余量；外部强制终止仍按重启恢复规则处理。
- 本运行控制只支持一个 CMDB 应用实例，不提供分布式租约或多副本调度保证。失败结果、运行日志与业务审计各自保留其职责，诊断输出不得代替任务和审计落库。
