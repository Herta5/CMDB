# CMDB 安全、权限与审计规范

## 文档职责

本文档定义 CMDB 的身份认证、会话安全、角色授权、项目隔离、云平台凭证保护、敏感信息输出和审计查询要求。用户名等领域身份契约由 [domain-model.md](domain-model.md) 定义；同步任务错误摘要必须同时遵守 [resource-sync.md](resource-sync.md#错误摘要与敏感信息) 的收敛规则。

## 身份认证与会话安全

- 用户密码必须为 12 至 72 字节；长度按提交值的实际字节数计算，以符合 bcrypt 的 72 字节输入边界。服务端只保存 bcrypt 哈希，不得保存、返回或记录明文密码。
- 用户不存在、密码错误或用户已停用时，登录接口必须返回相同的状态码、错误码和中文提示“用户名或密码错误”；不存在用户的校验路径也必须执行与有效 bcrypt 哈希可比的验证工作，避免通过响应内容或显著耗时差异枚举用户名。
- 登录成功后签发有效期固定为 24 小时、签名算法为 HS256 的 JWT。JWT 是客户端可解码内容，只允许包含用户名、全局角色和过期时间等最小公开声明；不得包含用户数字 ID、密码或密码哈希、项目成员关系、云凭证及其他敏感信息。
- 每个受保护请求都必须限定 HS256、校验签名和过期时间，并根据 JWT 中的用户名重新读取当前用户。后端必须以数据库中的当前用户状态、全局角色和项目成员关系执行授权，不得直接信任令牌中的历史角色或客户端提交的权限信息。
- 会话必须与创建令牌时的账户代际绑定，但不得为此向客户端暴露内部用户 ID。用户被停用或删除后，旧 JWT 必须立即失效；删除后使用同名用户名重建用户，旧 JWT 也不得绑定到新账户。
- 用户全局角色或项目成员关系变化后，旧 JWT 即使尚未到期，后续请求也只能获得变更后的当前权限，不得继续保留签发时的旧权限。

## 身份标识暴露边界

- 用户名是页面和公开 API 引用用户的唯一稳定标识。用户管理、项目负责人、项目成员、审计操作人筛选及用户类审计对象必须使用用户名；显示名称只用于辅助展示，不参与身份关联或权限判断。
- 后端必须根据已验证的用户名查得当前用户，再使用数据库内部 ID 完成成员关系、负责人和审计关联。不得信任客户端提交的内部用户 ID。
- 公开 API 的请求体、响应体、路径参数和查询参数，以及页面、浏览器状态、持久化存储、用户可见错误和审计详情，均不得暴露、接收或要求填写用户数字 ID。
- 数据库可以保留用户数字主键及外键，但这些字段只用于服务端内部的数据完整性和关联效率。

## 权限矩阵

“所属项目”指普通用户已建立成员关系且该关系授予对应角色的业务项目。系统管理员是 CMDB 的全局最高权限例外：下表所有能力均允许，访问任何项目级能力时无需预先建立项目成员关系。项目管理员和项目成员必须限制在所属项目内，不得因在一个项目中的角色获得其他项目权限。

| 对象或能力 | 系统管理员 | 所属项目的项目管理员 | 所属项目的项目成员 |
| --- | --- | --- | --- |
| 用户管理 | 允许查询公开用户资料，创建、编辑、启停和删除其他用户，并配置全局角色与项目权限 | 不允许 | 不允许 |
| 业务项目 | 允许查询全部项目，并创建、查看、编辑、启停和删除项目 | 只允许查看所属项目资料，不得修改项目基本资料、状态或删除项目 | 只允许查看所属项目资料 |
| 项目成员 | 允许查看和管理任意项目的成员关系 | 允许查看所属项目成员，并添加成员、修改角色或移除其他成员 | 只允许查看所属项目成员 |
| 成员候选用户 | 允许查询任意项目可添加的启用用户最小资料 | 允许查询所属项目可添加的启用用户最小资料 | 不允许 |
| 接入源 | 允许查看、创建、编辑、启停和删除任意项目接入源 | 允许查看、创建、编辑、启停和删除所属项目接入源 | 只允许查看所属项目接入源及脱敏状态 |
| 连接测试 | 允许对任意项目接入源执行 | 允许对所属项目接入源执行 | 不允许 |
| 手工同步与任务重试 | 允许对任意项目接入源执行 | 允许对所属项目接入源执行 | 不允许 |
| 云资源与访问端点 | 允许跨项目只读查询 | 允许只读查询所属项目 | 允许只读查询所属项目 |
| 同步任务历史与结果 | 允许跨项目只读查询 | 允许只读查询所属项目 | 允许只读查询所属项目 |
| 项目审计 | 允许查询任意项目 | 允许查询所属项目 | 不允许 |
| 全局审计 | 允许查询全局操作和全部项目审计 | 不允许 | 不允许 |

- 成员候选用户只允许返回用户名和显示名称等完成选人所需的最小公开资料，不得借此开放全局用户列表、邮箱、状态、全局角色或任何认证字段。
- 云资源、访问端点和云平台原始属性只能由同步模块维护；矩阵中的管理权限不得解释为允许人工编辑云端属性。
- 系统管理员是授权层的最高权限角色，但不能绕过云账号唯一归属、项目或接入源删除依赖及资源生命周期等领域不变量。
- 项目停用后仍必须保留项目归属及历史资产、任务和审计的授权只读查询。只有系统管理员可以维护该项目资料、重新启用或删除该项目；停用后不得为其执行新的连接测试、手工同步、重试或自动任务创建。项目或接入源在任务受理后才停用时，不得取消状态为 `queued` 或 `running` 的既有任务，任务必须继续处理并进入终态；恢复和执行边界按 [resource-sync.md](resource-sync.md#重试与服务重启恢复) 执行。

## 项目隔离与授权执行

- 所有受保护接口必须先完成身份认证。对于普通用户，所有项目级接口必须根据路径中的项目标识重新查询其当前项目成员关系和角色；系统管理员作为明确的全局例外，无需项目成员关系即可跨项目访问和管理。
- 后端必须以路径项目作为授权边界，查询参数、请求体中的项目标识或前端当前项目状态不得覆盖该边界。访问接入源、同步任务、云资源和访问端点等项目子对象时，还必须确认目标对象确实归属于路径项目。
- 对接入源、同步任务、云资源、访问端点等项目子对象，对象不存在与对象不属于路径项目必须返回同一状态码、错误码和中文提示；响应和审计不得披露该对象是否存在或其真实归属。
- 前端可以按当前角色隐藏或禁用入口以改善体验，但前端路由守卫、按钮隐藏和客户端缓存均不能替代后端授权。每次写操作和敏感读取都必须在后端重新校验。
- 普通用户访问无权项目与访问不存在项目时，必须返回完全一致的状态码、错误码和中文提示；在完成项目授权前不得查询或披露该项目下接入源、资源、任务或审计是否存在。
- 禁止通过项目负责人字段、接入源所有者、审计操作人或前端传入角色推导项目权限。只有当前全局角色和当前项目成员关系可以参与授权。

## 自我保护

- 系统管理员不得删除、停用自己，也不得把自己的全局角色降级为普通用户；这些约束必须由后端执行，不能只依赖页面禁用按钮。
- 项目管理员可以修改自己在当前项目中的角色，包括降级为项目成员；角色变更必须立即生效，后续请求不得继续保留项目管理员权限。项目级自我保护只禁止项目管理员移除自己的成员关系。若角色变化后项目中没有项目管理员，必须由系统管理员执行全局纠正操作；系统管理员不受该项目级自我移除限制。
- 自我保护被触发时必须返回稳定的中文业务错误，不得执行部分更新，也不得留下与实际结果不一致的成功审计。

## 外部传输安全

- CMDB 主动访问非本机回环地址的 HTTP 类外部服务时必须使用 HTTPS，并执行正常的 TLS 证书链和目标主机名校验；不得在 HTTPS 失败后自动或人工回退为明文 HTTP，也不得跟随会把请求降级为 HTTP 的重定向。云平台身份识别、连接探测、资源列表、分页、详情和补充信息等全部 API 调用均受此约束。
- 云 SDK 必须通过显式客户端配置或受进程内传输回归测试保护的 SDK 默认值使用 HTTPS。已知 SDK 默认协议可能为 HTTP 时，平台模块必须显式覆盖为 HTTPS，不能依赖某个云产品当前兼容 HTTP；新增云平台、产品、API 或自定义外部端点时必须同步加入协议验收。
- `localhost`、IPv4 `127.0.0.0/8` 和 IPv6 `::1` 是本机回环地址，仅用于不会离开本机的健康检查和开发代理时可以使用 HTTP；该例外不得用于云平台 API、携带云凭证的请求或返回云资产数据的外部调用。DNS、数据库等非 HTTP 协议不以 HTTPS 替代，但必须遵守各自的安全传输要求。

## 凭证加密与更新

- 云平台凭证必须使用部署环境提供的 `CMDB_ENCRYPTION_KEY` 派生 256 位数据加密密钥，并使用 AES-256-GCM 和每次加密随机生成的 nonce 完成机密性与完整性保护。原始主密钥不得写入数据库或业务配置，不得出现在进程输出和诊断信息中。
- 明文云凭证只允许在内存中的最短调用链用于对应平台身份识别、连接探测和资源采集；阿里云与 AWS 的全部云 API 请求必须遵守[外部传输安全](#外部传输安全)，不得依赖可能回退到 HTTP 的 SDK 历史默认值。
- 接入源只允许持久化加密后的完整凭证和非敏感配置；区域、同步周期等非敏感配置字段不得被用于保存密码、令牌、AccessKey、主加密密钥或完整密文。
- 新建接入源必须显式提交对应平台字段白名单内的完整凭证，并在加密前完成严格结构校验和联网账号识别；非敏感配置首期只允许空对象。接入源响应和页面只显示“已安全配置”等不含凭证片段的脱敏提示，不得返回稳定云账号标识、身份验证时间、密文、回填明文或根据 AccessKey 前后缀生成可识别提示。
- 编辑接入源时，凭证字段缺失、`null` 或空字符串表示保留原凭证；空对象和部分字段不是“保留”语义，必须按不完整凭证拒绝。只有用户显式提交完整的新凭证时才允许联网确认仍为原账号，并加密整体替换。身份不一致或任一步失败时必须继续保留原密文、配置和身份，不得出现部分字段混用。
- 创建与显式替换凭证时，凭证对象必须严格拒绝未知字段、重复字段与尾随 JSON；凭证校验、联网身份识别、唯一性判断、加密保存和审计必须原子一致，失败不得产生成功审计。
- 创建与编辑请求外层同样必须在进入领域服务前严格拒绝未知字段与尾随 JSON。当前入口解析尚未实现这一边界，不能以凭证对象的严格校验替代；交付状态与剩余差距见 [implementation-status.md](implementation-status.md)。
- 明文凭证只允许在创建、显式替换、连接测试和资源采集所需的最短调用链内存在；使用完成后不得放入可长期存活的页面状态、任务结果、缓存、日志或审计详情。

## 数据库首次初始化边界

- CMDB 当前只支持 PostgreSQL 17 空库首次初始化。Docker Compose 部署必须使用新建空数据卷，由 PostgreSQL 官方初始化流程依次执行 `001_create_app_role.sh` 和 `002_schema.sql`；文件编号只表示首次初始化顺序，不表示结构版本或增量变化。
- `001_create_app_role.sh` 使用 PostgreSQL 管理员身份创建受限 `cmdb` 应用账号；`002_schema.sql` 一次性创建当前完整业务结构并授予应用账号所需权限。生产应用数据库账号只能执行正常业务读写，不得拥有建表、改表等 DDL 权限。
- PostgreSQL 管理员密码与 `cmdb` 应用账号密码必须均为非空且彼此不同，只允许通过首次初始化所需的最短通道传递；管理员账号不得配置给长期运行的应用服务。初始化输出不得泄露密码、完整连接信息、SQL 参数或底层数据库错误正文。
- 当前项目尚无已发布版本和受支持的存量安装，不提供结构版本表、数据库结构转换命令或已有数据库兼容处理。已有数据库、已有数据卷及非空目标库不得直接套用首次初始化流程。

## 敏感信息保护

- 密码与密码哈希、会话及刷新令牌、AccessKey 及其 Secret、API Key、客户端 Secret、完整云凭证、`CMDB_ENCRYPTION_KEY`、PostgreSQL 管理员密码、完整密文、`Authorization` 请求头，以及云平台或数据库原始错误响应和请求响应正文，均为敏感信息，除下述必要处理边界外属于禁止披露项。
- 会话令牌和提交凭证只允许出现在认证或凭证输入所必需的最小瞬时通道，例如登录响应中的 JWT、认证请求头和凭证输入提交；云凭证在服务端的使用继续遵守“凭证加密与更新”的最短调用链要求。必要传递不得扩展为无关响应、错误摘要、应用日志、审计日志、长期页面状态或持久浏览器状态；使用结束后必须清理瞬时输入与传递状态。
- 敏感信息不得进入业务持久化中的非凭证字段；仅允许前述密码专用字段保存 bcrypt 哈希、云凭证专用字段保存加密凭证，不得持久化会话令牌或明文凭证。真实秘密不得进入测试输出、测试快照、测试夹具或代码仓库；明确虚构且不具备真实访问能力的测试数据允许进入隔离测试夹具，但受测响应、日志、审计和页面仍须验证过滤与清理边界。自动测试只使用虚构凭证和模拟云响应，不得访问真实云账号。
- 所有业务错误在返回、持久化或审计前必须收敛为中文安全摘要或有限的业务错误分类；不得依赖前端或日志展示层临时脱敏。连接测试和同步任务还必须遵守 [resource-sync.md](resource-sync.md#错误摘要与敏感信息) 的专门边界。
- 创建和编辑接入源的内部故障使用安全 `500`，只有有限的可纠正输入错误才返回 `400`；错误类别按领域身份判断，不以错误字符串匹配。连接探测与账号身份识别分别遵守 [接入源与连接测试](resource-sync.md#接入源与连接测试) 的错误契约；创建和替换凭证的账号身份识别可按认证、身份查询权限和网络类别返回可操作的固定中文提示，但任何分类都不得泄露数据库或云响应正文。
- 手工同步与连接测试读取接入源发生内部故障时，返回固定中文摘要及 `500 SOURCE_SERVICE_UNAVAILABLE`，不得伪装为对象不存在；真实不存在与跨项目来源仍保持同一 `404 SOURCE_NOT_FOUND`，读取失败没有业务或审计副作用。
- 审计详情必须在持久化前递归删除嵌套对象与数组中的敏感字段和内部用户引用；新增或重命名敏感字段必须在发布前加入共享敏感键分类与回归测试。运行时负责递归过滤已统一分类的键，不负责猜测未知字段语义；不得由各业务模块各自维护遗漏风险不同的过滤逻辑，也不引入审计字段允许列表。任务统计、平台名称、资源类型和安全结果分类可以保留，但不得附带底层 SDK 错误、堆栈、原始载荷或凭证片段。

## 审计动作与一致性

- 下列重要动作必须进入统一审计：用户创建、资料或密码修改、角色与状态变化、删除；项目创建、资料或状态变化、删除；项目成员添加、角色变化和移除；接入源创建、编辑、凭证替换、启停和删除；连接测试；自动同步、手工同步和重试结果。资源新增、真实更新、恢复、失联和物理删除仍是重要审计事实，但同一次同步只写一条 `source.synced`，在其详情中按五种动作、资源类型和全部云端唯一 ID 分类记录。
- 幂等同步中只有最近发现时间或易变观测属性变化时不得进入 `source.synced` 变化清单。连接测试和同步失败可以记录安全结果分类，采集失败不得伪造资源失联、恢复或删除事实。
- 审计必须与所描述的业务变化保持一致。业务变更需要审计时，两者必须在同一事务中提交或一同回滚；资源同步的事务边界以 [resource-sync.md](resource-sync.md#事务与一致性边界) 为准。
- 人工请求必须记录操作人用户名和显示名称快照、可信请求来源 IP、动作、对象类型、稳定对象标识、脱敏详情和发生时间；存在项目上下文时还必须记录项目归属，全局用户操作等没有项目上下文的审计保持项目归属为空。接入源相关审计还必须保存操作发生时的接入源名称快照，页面以该快照展示对象名称，不得以接入源数据库 ID 冒充名称。用户类对象必须以用户名作为对象标识，内部操作人 ID 即使为数据库关联所需也不得公开。
- 自动调度、服务重启恢复等无人工请求的后台操作必须明确记录为“系统任务”，操作人保持为空，不得借用系统管理员身份或伪造请求 IP。人工请求进入后台执行时，只允许传递已认证操作人的最小审计快照，不得传递 JWT、密码或完整用户对象。

## 审计查询、分页与保留

- 系统管理员可以通过全局审计查询全局操作和所有项目记录；项目管理员只能通过路径项目查询所属项目记录；项目成员不得查询项目审计。审计查询仍须在后端执行本文件定义的实时授权。
- 审计查询支持按所属查询上下文、时间范围、动作、操作人用户名、对象类型和对象标识进行精确筛选，并提供服务端分页。筛选用户和用户类对象时只接受用户名，不得把内部用户 ID 作为查询入口。
- 第一次分页查询必须返回固定的审计快照边界，后续页携带同一 `snapshot_id`，并按发生时间倒序、审计记录 ID 倒序的稳定次序查询。翻页期间新产生的审计不得进入该次固定快照，避免稳定分页出现重复或遗漏。筛选条件变化时，客户端必须丢弃原 `snapshot_id` 并通过新查询获取新快照；服务端只需将客户端提交的 `snapshot_id` 作为当前筛选的查询上界，无需保存快照与筛选条件的绑定状态。
- 审计日志必须仅追加、长期保留，不得因用户、项目、成员关系、接入源、同步任务或云资源删除而级联删除。删除对象前必须保存足以追溯的用户名、显示名称、项目名称、接入源名称或云端唯一 ID 等非敏感快照；同步资源物理删除后，唯一 `source.synced` 聚合详情中的云端唯一 ID 继续可追溯。一次性人工清空既有审计仅属于本次交付操作，不授权后续删除或自动清理，新审计继续适用仅追加、长期保留规则。
- 查询和展示历史审计时仍必须执行敏感信息过滤及内部用户 ID 清理；历史记录缺少可信公开快照时不得猜测、反查或暴露内部身份。
