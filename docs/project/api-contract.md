# CMDB 公开接口契约与生成规则

## 职责与权威边界

本文定义公开 HTTP 接口的维护、生成和验收要求。`api/openapi.yaml` 及其引用文件是 HTTP 路径、方法、参数、响应结构与状态码的唯一契约来源；项目权限、凭证保护和资产生命周期仍分别以 [security.md](security.md)、[domain-model.md](domain-model.md) 和 [resource-sync.md](resource-sync.md) 为准。发现契约与产品规范冲突时必须按项目协作约束处理，不得通过放松 Schema 隐藏冲突。

## 覆盖范围与结构

- OpenAPI 必须覆盖 `/health` 和全部 `/api/v1` 业务操作，包括登录、当前身份、用户、项目、成员与候选人、接入源、连接测试、资源、同步任务及审计。静态控制台文件不作为业务 API。
- 个人设置包含 `updateMyProfile`（`PUT /api/v1/me/profile`，成功返回公开用户）和 `changeMyPassword`（`PUT /api/v1/me/password`，成功返回 `204`）。均显式要求当前身份认证，严格拒绝未知字段、重复字段和尾随 JSON；密码字段为仅写入字段，错误不回显输入。
- 每个操作必须具有非空、全局唯一且稳定的 `operationId`，声明所有实际可产生的成功状态及有限错误响应；新增操作必须同时补齐路由、认证授权策略和验收。
- 请求与响应字段使用现有 snake_case；成功响应直接返回公开资源或分页结构，业务错误返回字符串 `code` 和中文 `message`。可信请求关联通过 `X-Request-ID` 响应头传递，不将原始错误塞入业务响应。
- 查询参数的非法类型（例如数字参数传入非数字字符串）必须返回安全 `400`，不得静默转换为零值；缺失参数与合法整数的既有默认规则由相应操作定义。
- 必须明确必填与可选、缺失与 `null`、空数组与空对象的区别。不得以宽泛的 `any` 或任意属性对象取代已知的用户、项目、接入源、资源、任务结构；确实动态的审计详情按现有递归敏感信息过滤规则处理。
- 用户引用只使用用户名；接口 DTO 不得包含用户数字主键、密码哈希、加密凭证、身份验证时间或云资源原始属性。接入源响应 DTO 允许包含只读字符串 `cloud_account_id`，值由云平台身份识别获得，供有查看权限的用户在卡片中完整核对账号；该字段不属于创建或编辑请求，不扩大错误、日志、审计输出范围。登录令牌和凭证提交仅按安全规范允许的最短通道传递。

## 后端与前端边界

- 从同一契约生成 Go 的 HTTP 类型和 Gin 严格服务端接口；手写 HTTP 适配负责安全错误映射及领域输入输出转换。领域服务、仓储和 GORM 模型不得依赖生成类型，持久化字段不得自动进入公开响应。
- 结构生成不能代替运行输入校验。JSON 解码、Schema 校验与领域业务校验必须各自保留，校验器原始错误和输入值不得进入用户响应、诊断或审计。
- 所有受保护请求先完成身份认证；项目授权必须在读取项目子对象之前执行，授权以路径项目和当前数据库事实为准。生成的认证声明不自动授予任何角色，也不能替代防枚举和系统管理员例外规则。
- 接入源请求严格拒绝未知外层字段和尾随 JSON。凭证必须在普通解码丢失重复键信息之前执行严格校验；更新时缺失、`null` 和空字符串保留原凭证，空对象与不完整凭证仍须拒绝。详细规则由 [security.md](security.md#凭证加密与更新) 定义。
- 前端从契约生成类型和 Axios 客户端。业务模块通过生成调用访问 API，仅保留确有展示需求的有类型转换，不重复手写传输 DTO 或以类型断言掩盖字段不符。
- 共享请求通道必须保留内存会话、请求发起时的会话绑定、旧请求的 `401` 不得清除新会话、超时、取消和中文错误提示。生成客户端不得新增令牌持久化或延长明文凭证寿命。

## 生成与变更检查

- 固定规范与工具版本，生成代码纳入版本控制并明确禁止手工修改；本地和 CI 使用同一生成入口。
- 修改契约后必须重新生成双端产物。CI 重新生成后若发现内容变化或未纳入版本控制的生成文件，必须失败。
- PR 必须与目标分支 merge-base 的完整契约比较，不得将当前版本与自身比较。首次引入契约可明确建立基线；基线存在后，删除操作、收紧输入或改变响应类型等不兼容变化必须被检查并阻止意外合并。
- 确需不兼容业务变更时，必须先完成用户确认、版本与调用方迁移安排，不能靠静默跳过兼容检查交付。
- 文档从相同契约生成离线产物；示例只使用虚构数据，不把生产令牌、密码或云凭证写入规范，也不默认新增公开在线调试入口。

## 验证标准

- 真实注册路由与契约的路径、方法、操作集合必须一致；遗漏契约或未实现操作均须失败。
- 真实 HTTP 测试必须校验成功和失败响应，覆盖认证、授权、公开字段及凭证输入；验证中不得输出含敏感信息的正文或校验器原始错误。
- 负向测试必须证明字段类型变化、缺失必填字段、意外公开字段和未声明状态可被门禁检测。类型生成和编译通过不能替代授权、事务及生命周期回归。
- 交付必须通过后端全量测试、隔离 PostgreSQL 17 集成测试、前端完整测试、类型检查、生产构建及契约生成检查；当前实现证据和差距见 [implementation-status.md](implementation-status.md)。
