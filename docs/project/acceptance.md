# CMDB 端到端产品验收标准

## 文档职责

本文档把 [产品定位与首期范围](overview.md)、[领域模型与资产状态](domain-model.md)、[云资源同步规范](resource-sync.md)、[安全、权限与审计规范](security.md) 和 [前端体验规范](frontend-guidelines.md) 中的强制要求转换为可执行场景。本文档只定义如何验收，不新增业务规则；规则发生变化时，必须先修改对应主责规范，再同步调整场景。

## 执行约定

- 每个场景必须从前置条件开始独立准备数据，不得依赖其他场景遗留的数据库、缓存、浏览器状态或任务状态。
- 涉及阿里云或 AWS 的连接测试与资源采集时，只能使用虚构凭证、采集器接口和模拟响应，不得连接真实云账号。模拟响应必须能按资源类型分别控制成功、失败、空结果、稳定字段变化和易变观测变化。
- 涉及时间的场景使用可控时钟；“24 小时”按精确失联开始时间计算，不以自然日替代。
- 标记为“安全场景”的场景必须在同一次执行中同时检查接口响应、应用日志、审计记录和页面状态。各场景中的“不泄露禁止披露项”均按 [敏感信息保护](security.md#敏感信息保护) 区分必要认证传递、凭证瞬时输入与禁止泄露：允许登录响应签发 JWT、认证请求头传递令牌及提交凭证的最小瞬时通道，使用后清理；日志、审计、无关响应、长期页面状态和持久浏览器状态不得留存敏感信息。明确虚构的数据可放入隔离测试夹具，不能用真实秘密；受测四个检查面的过滤断言不因使用虚构数据而免除，用户数字 ID 始终不得公开。
- 验收同时覆盖后端强制校验与前端体验。隐藏入口或禁用按钮不能代替直接调用接口验证授权；页面展示正确也不能代替数据库事务、审计和资源状态检查。

## 产品范围与模块边界

### AC-001 产品名称、定位与范围边界

**前置条件**

- 准备可检查的控制台构建产物、公开接口说明、部署配置和项目规范入口。

**操作**

1. 检查页面标题、用户可见文案、接口说明和部署配置中的产品名称与定位。
2. 检查控制台和公开接口提供的云平台、资源类型及资产操作。
3. 尝试查找云资源编排、费用管理、监控告警、工单处理、向云端写回属性、手机端专项适配及其他未确认能力的可操作入口。

**预期结果**

- 产品名称统一为“CMDB”，定位为面向公有云的资源配置管理平台，业务项目体现为数据归属和普通用户权限隔离的最高边界。
- 首期仅包含阿里云 ECS、RDS、SLB、ALB、NLB、GWLB 与 AWS EC2、RDS、CLB、ALB、NLB、GWLB；不存在未获确认的新云平台或资源类型。
- 不提供云资源编排、费用管理、监控告警、工单、向云端写回属性、独立部署的云采集微服务或手机端专项布局，也不采集或结构化 Target Group、Server Group、后端服务器、健康检查、转发规则、证书、TLS 策略或跨 Region 自动发现。
- 任何新增上述范围外能力的交付必须有用户确认及同步更新后的 `overview.md`，不能仅由实现或本验收文档改变范围。

### AC-002 统一入口与云平台模块边界

**前置条件**

- 系统已装配阿里云与 AWS 的模拟采集器，两者分别返回平台特有的虚构认证字段，以及阿里云 `ecs`、`rds`、`slb`、`alb`、`nlb`、`gwlb` 和 AWS `ec2`、`rds`、`clb`、`alb`、`nlb`、`gwlb` 响应。

**操作**

1. 从左侧“管理”分组进入“云同步管理”，分别创建阿里云和 AWS 接入源并执行模拟连接测试。
2. 检查两类接入源的凭证表单、采集器调用及产生的任务、资源、端点、状态和审计记录；核对两平台预期类型顺序和旧 `elb` 不再产生。

**预期结果**

- 控制台只有统一的“云同步管理”入口，阿里云与 AWS 凭证格式和采集调用保持清晰分离。
- 两个平台在同一个 CMDB 服务中运行，通过统一接口接入公共的项目归属、接入源、任务、资源、端点、资产状态、权限和审计能力。
- 公共能力的行为和数据模型一致，不在两个平台模块中形成两套权限、同步、生命周期或审计规则。
- 阿里云预期类型按 `ecs`、`rds`、`slb`、`alb`、`nlb`、`gwlb` 返回，AWS 按 `ec2`、`rds`、`clb`、`alb`、`nlb`、`gwlb` 返回；同名 `alb`、`nlb`、`gwlb` 由平台区分，旧通用 `elb` 不出现在资源、任务统计、页面查询或审计标签中。

## 身份、用户与权限

### AC-003 首次初始化与成功登录（安全场景）

**前置条件**

- 使用空用户库启动系统；准备符合 12 至 72 字节约束的虚构管理员用户名和密码。

**操作**

1. 完成首次管理员初始化并登录。
2. 解码但不信任返回的 JWT，检查声明、签名算法和有效期；使用令牌访问受保护页面和接口。
3. 同时检查接口响应、应用日志、初始化与登录审计、页面状态和浏览器持久化存储。

**预期结果**

- 只创建一名系统管理员；密码仅以 bcrypt 哈希保存，登录成功并签发 HS256、固定 24 小时有效的 JWT。
- JWT 只包含用户名、全局角色、过期时间等最小公开声明，不含用户数字 ID、密码、哈希、项目成员关系或云凭证；会话与账户代际的绑定机制不得向客户端暴露内部标识。
- 页面进入系统管理员可用的 CMDB 控制台；登录响应和认证请求头允许必要令牌传递，密码输入与传递状态在使用后清理，不在长期页面状态或浏览器持久化保存密码、令牌或用户数字 ID。
- 接口响应除必要登录令牌外、应用日志、审计和长期页面状态均不泄露禁止披露项；审计中的用户对象标识使用用户名。

### AC-004 登录失败、防枚举与密码边界（安全场景）

**前置条件**

- 存在一名启用用户和一名停用用户；准备不存在的用户名、错误密码，以及按 UTF-8 实际字节数分别为 11、12、72、73 字节的密码样本。

**操作**

1. 分别使用不存在用户、错误密码和停用用户登录，并在可重复环境下比较验证路径与响应耗时分布。
2. 分别提交四个边界密码样本执行创建或改密。
3. 检查接口响应、应用日志、审计、登录页错误与提交状态。

**预期结果**

- 三种登录失败返回完全相同的状态码、错误码和中文提示“用户名或密码错误”；不存在用户也执行与有效 bcrypt 哈希可比的验证工作，无显著可枚举耗时差异。
- 12 和 72 字节密码可通过长度校验，11 和 73 字节密码被中文校验错误拒绝；任何情况下都不保存或输出明文密码。
- 失败响应、应用日志、审计和页面状态均不披露用户是否存在、停用状态、密码、哈希、内部 ID 或其他禁止披露项。

### AC-005 会话失效与实时权限（安全场景）

**前置条件**

- 一名启用用户持有有效 JWT，并同时具有全局角色和某项目成员关系；记录该令牌对应的账户代际。

**操作**

1. 依次修改该用户的全局角色、项目角色和项目成员关系，每次均用旧 JWT 请求对应受保护能力。
2. 停用并删除该用户后再次使用旧 JWT；随后以同名用户名重建用户并再次使用旧 JWT。
3. 使用伪造算法、无效签名、过期令牌及客户端提交的虚假角色请求接口。
4. 检查接口响应、应用日志、权限审计和页面状态。

**预期结果**

- 每次请求均限定 HS256、验证签名与过期时间，并由用户名重新读取当前账户、全局角色和当前成员关系；角色或成员关系变化立即影响旧 JWT 的后续权限。
- 停用、删除及同名重建后旧 JWT 均无效，旧令牌不能绑定到新账户。
- 伪造算法、签名、过期令牌和客户端虚假角色均不能获得权限；页面停止展示受保护数据并进入统一无权限状态。
- 响应、日志、审计与页面均不披露令牌、内部用户 ID、账户代际实现或目标项目数据。

### AC-006 用户名公开契约（安全场景）

**前置条件**

- 准备用户名重复、修改用户名、空值、65 字符、含中文、连字符或空格等非法样本，以及符合 `^[A-Za-z0-9_]+$` 的合法样本。

**操作**

1. 通过用户管理、项目负责人、项目成员、候选用户、审计筛选、用户类审计对象及相应页面执行创建、引用、查询和修改。
2. 尝试在请求体、路径、查询、路由和浏览器状态中提交或查找用户数字 ID，并检查显示名称是否被错误用作身份值。
3. 检查接口响应、应用日志、审计和页面状态。

**预期结果**

- 用户名全局唯一、创建后不可修改，长度 1 至 64 且只接受 ASCII 字母、数字和下划线；前后端均以中文提示拒绝非法值。
- 所有公开引用、选择、筛选、路由和用户类审计对象标识只使用用户名；显示名称可辅助展示但不参与关联、传参或权限判断。
- 客户端不能提交、看到、存储或被要求填写用户数字 ID；后端只在内部完成用户名与主键转换。
- 响应、日志、审计详情与页面状态均不泄露内部用户 ID 或其他禁止披露项。

### AC-007 系统管理员最高权限（安全场景）

**前置条件**

- 系统管理员未加入项目甲和项目乙；两个项目均已有成员、接入源、资源、任务和审计。

**操作**

1. 以系统管理员查询和管理用户、两个项目、项目成员和具体项目接入源。
2. 在具体项目上下文执行连接测试、手工同步与允许的任务重试，跨项目只读查询资源、端点、任务和项目审计，并查询全局审计。
3. 检查接口响应、应用日志、审计和页面入口、数据与操作状态。

**预期结果**

- 系统管理员无需项目成员关系即可完成权限矩阵中所有允许能力，并能配置全局角色与项目权限。
- 最高权限只允许绕过项目成员授权，不允许绕过云账号唯一归属、父对象删除依赖或资源生命周期等领域不变量。
- 用户管理入口只对系统管理员可见；跨项目记录明确显示所属项目，项目级写操作仍以选定的具体路径项目为边界。
- 响应、日志、审计和页面不泄露禁止披露项；每项写操作生成与实际结果一致的审计。

### AC-008 项目管理员与项目成员权限矩阵（安全场景）

**前置条件**

- 项目甲包含项目管理员和项目成员，项目乙无二者成员关系；两项目均有完整测试数据。

**操作**

1. 以项目管理员在项目甲查看项目资料、管理成员与接入源、查询候选用户、执行连接测试和手工同步、重试失败任务，并查询资产、端点、任务和项目审计。
2. 尝试修改项目甲基本资料或状态、删除项目、管理全局用户或查询全局审计。
3. 以项目成员在项目甲只读查询项目资料、成员、脱敏接入源、资产、端点和同步结果，并尝试候选用户、接入源写操作、连接测试、同步、重试及项目审计。
4. 检查接口响应、应用日志、审计及导航、按钮、路由和无权限页面。

**预期结果**

- 两个角色仅在项目甲获得规范矩阵中明确允许的能力；项目管理员不能修改项目基本资料、状态或删除项目，项目成员没有管理及审计权限。
- 候选用户接口对项目管理员只返回启用用户的用户名、显示名称等最小选人资料，不扩展为全局用户列表或泄露邮箱、状态、全局角色、认证字段。
- 被拒操作无业务变化和成功审计；页面入口与按钮按权限隐藏或禁用，直接调用接口仍由后端拒绝并呈现无权限状态。
- 响应、日志、审计和页面均不泄露项目乙数据、内部用户 ID 或其他禁止披露项。

### AC-009 成员、负责人和自我保护（安全场景）

**前置条件**

- 项目甲有负责人、两名项目管理员和一名成员；另有一名系统管理员；记录全部关系和审计基线。

**操作**

1. 将用户设为项目负责人但不添加成员，验证权限；删除负责人用户。
2. 重复添加同一成员；让项目管理员修改自己的项目角色、移除自己的成员关系和移除其他成员。
3. 让系统管理员移除任意成员；尝试让系统管理员删除、停用自己或把自己降级为普通用户。
4. 检查接口响应、应用日志、审计和页面状态。

**预期结果**

- 负责人字段不创建成员关系也不授予权限；负责人被删除后字段置空。同一用户在同一项目最多一条成员关系，项目角色只有 `project_admin` 与 `member`，系统管理员不是项目角色。
- 项目管理员可立即将自己降级，后续请求按新权限执行；不得移除自己的成员关系，但可移除其他成员。项目无管理员时只能由系统管理员纠正，系统管理员可移除任意项目成员。
- 系统管理员不能删除、停用自己或自我降级。所有自我保护由后端原子拒绝，返回稳定中文错误，不产生部分更新或虚假成功审计。
- 响应、日志、审计和页面不泄露内部用户 ID 或禁止披露项，审计用户标识为用户名。

### AC-010 跨项目隔离与防枚举（安全场景）

**前置条件**

- 普通用户只属于项目甲；项目乙存在接入源、任务、三类资源、端点和审计；另准备不存在的项目及对象标识。

**操作**

1. 用项目乙和不存在项目的路径分别请求项目及其接入源、任务、资源、端点、审计。
2. 在项目甲路径中通过查询参数、请求体、前端项目状态或项目乙对象标识尝试覆盖项目边界。
3. 将该用户设置为项目乙负责人、某接入源相关展示字段或项目乙审计操作人，但不建立项目乙成员关系，再请求项目乙数据。
4. 变更该用户在项目甲的当前角色后，用缓存页面和原请求再次操作。
5. 检查接口响应、应用日志、拒绝审计和页面状态。

**预期结果**

- 无权项目与不存在项目返回完全相同的状态码、错误码和中文提示；子对象不存在与不属于路径项目也返回完全一致的结果。
- 后端在授权前不查询或披露目标项目的子对象存在性与真实归属，路径项目不能被参数、请求体、缓存或前端角色覆盖。
- 权限只由当前全局角色和路径项目的当前成员关系决定，不能由项目负责人、接入源相关展示字段、审计操作人或前端传入角色推导。
- 每次敏感读取和写操作都重新验证当前成员关系与角色；页面清除受保护详情并展示统一无权限状态。
- 响应、日志、审计和页面均不泄露项目乙名称、数据、对象存在性、真实归属、内部 ID 或其他禁止披露项。

### AC-011 项目与接入源归属约束

**前置条件**

- 项目甲和项目乙已启用；平台适配器使用虚构凭证和模拟 STS 响应返回稳定账号标识，项目甲已有项目编码和一个接入源。

**操作**

1. 尝试创建重复项目编码并修改已创建项目的编码；修改名称与描述。
2. 使用不同显示名称或凭证，在项目甲和项目乙分别重复创建模拟响应为同平台同账号的接入源；再以两个并发事务创建同一账号，并尝试把项目甲接入源迁移至项目乙。
3. 尝试通过普通编辑修改 `provider`、稳定云账号标识或身份验证时间；从项目甲接入源产生模拟任务、资源和端点，检查其项目归属。

**预期结果**

- 项目编码全局唯一且创建后不可修改；有权限时可修改项目名称和描述。项目状态只有“启用”和“停用”。
- 同平台同云账号或云租户在同一项目和跨项目均不能重复接入，凭证、名称或并发请求不能绕过；服务返回不披露既有归属的稳定 `409`，数据库非条件唯一约束保证并发时只有一个事务成功。
- 接入源的项目、平台和稳定账号身份不可由普通编辑改变；账号标识和身份验证时间始终非空并满足数据库一致性约束，接入源不能跨项目迁移且只属于一个项目。
- 任务、资源、端点、统计和审计全部继承接入源的项目甲归属，不写入项目乙；端点不能独立改变项目归属。

### AC-012 创建接入源、默认值与加密（安全场景）

**前置条件**

- 在具体启用项目中以有权限用户进入云同步管理；配置虚构的 `CMDB_ENCRYPTION_KEY`，准备两平台完整凭证、凭证对象字段缺失/空白/未知/重复/非字符串样本、创建请求外层未知字段/尾随 JSON 样本、非空配置及模拟身份识别成功和失败结果。

**操作**

1. 分别创建阿里云和 AWS 接入源，只提交名称、区域、完整凭证和空配置，不提交云账号标识、启用状态和同步周期；由模拟 STS 返回稳定账号标识，并检查两平台 SDK 构造的出站身份请求协议。
2. 分别提交非法凭证对象、非空配置、认证/权限/网络失败、空值或格式错误的账号响应，再制造唯一冲突和持久化失败。
3. 分别提交包含未知字段或尾随 JSON 的创建请求外层载荷，检查请求是否在进入领域服务前被拒绝。
4. 检查数据库凭证字段、nonce、非空 `cloud_account_id`、非空 `identity_verified_at`、普通配置字段、响应与页面；用相同明文重复加密作比较。
5. 检查接口响应、应用日志与进程输出、创建审计和页面/浏览器状态。

**预期结果**

- 阿里云凭证对象只接受 `access_key_id`、`access_key_secret`，AWS 凭证对象只接受 `access_key_id`、`secret_access_key` 和可选 `session_token` 的非空字符串完整集合；凭证对象内的未知、重复、部分、空白、非字符串、非对象、尾随 JSON 及首期非空配置都在加密和联网前以中文参数错误拒绝。
- 创建请求外层同样必须拒绝未知字段和尾随 JSON；当前入口尚未实现这一严格解析，相关样本用于暴露已知差距，在补齐实现与回归测试前 AC-012 不得判定为完整通过。
- 合法新接入源先经单次模拟 STS 轻量识别，再将稳定账号标识和验证时间原子保存；默认启用、默认周期 60 分钟，并正确保存最近/下次同步时间字段语义。身份识别、唯一冲突或持久化失败时不保存接入源、新密文或成功审计。
- 阿里云和 AWS 的 STS 身份请求均使用 HTTPS；阿里云实现不得回退到 SDK 的历史 HTTP 默认协议，AWS SDK 的 HTTPS 默认行为必须有进程内传输回归测试保护。协议验收不得连接真实云账号或使用真实凭证。
- 基础字段、周期、凭证和配置无效返回 `400 SOURCE_INVALID_INPUT`；云身份认证、身份查询权限和网络失败均返回 `502 CLOUD_IDENTITY_UNAVAILABLE`，并分别提示检查凭证、检查授权或检查服务端网络。注入真实事务或审计写入后的内部故障返回 `500 SOURCE_SERVICE_UNAVAILABLE`，已执行的来源与审计写入一并回滚，响应不包含内部原文。
- 凭证使用由环境主密钥派生的 256 位密钥和 AES-256-GCM 随机 nonce 加密，相同明文不会产生相同完整密文。
- 数据库只在凭证专用字段保存完整密文；区域、周期等非敏感字段不承载密码、令牌、AccessKey、主密钥或完整密文，原始主密钥不进入数据库或业务配置。
- 响应和页面仅显示“已安全配置”等无凭证片段状态，不返回或回填稳定账号标识、身份验证时间、明文、密文及 AccessKey 前后缀。
- 响应、应用日志/进程输出、审计和页面/浏览器状态均不泄露禁止披露项，创建与审计原子一致。

### AC-013 保留与原子替换凭证（安全场景）

**前置条件**

- 已有使用虚构完整凭证 A 的接入源，并能通过模拟适配器返回当前稳定账号；准备返回相同账号的完整凭证 B、返回不同账号的完整凭证 C、编辑请求外层未知字段/尾随 JSON 样本，以及可注入的云调用和持久化失败。

**操作**

1. 编辑非敏感配置时省略凭证，再以空凭证提交，分别验证后续连接测试仍使用 A。
2. 显式提交完整凭证 B，验证联网识别为原账号后整体替换；再分别用凭证 C、身份识别失败和持久化失败尝试替换。
3. 尝试只提交 AccessKey 或 Secret 等部分凭证；另分别提交包含未知字段或尾随 JSON 的编辑请求外层载荷。
4. 检查接口响应、应用日志、编辑及凭证替换审计、页面和浏览器状态。

**预期结果**

- 凭证缺失、`null` 或空字符串均保留原密文 A；空对象和部分凭证被中文校验错误拒绝。只有显式完整凭证 B 联网识别为原稳定账号后，才整体重新加密替换。
- 编辑请求外层同样必须拒绝未知字段和尾随 JSON；当前入口尚未实现这一严格解析，相关样本用于暴露已知差距，在补齐实现与回归测试前 AC-013 不得判定为完整通过。
- 凭证 C 指向其他账号时返回稳定 `409`；身份识别的认证、权限和网络失败均返回 `502 CLOUD_IDENTITY_UNAVAILABLE`，并分别提示检查凭证、检查授权或检查服务端网络。凭证校验、身份比对、加密、更新与审计保持原子；任一步失败后仍完整保留替换前密文、配置、账号身份和验证时间，不出现字段混用或成功审计。
- 编辑的有限输入错误保持 `400`；读取、事务、审计或其他内部依赖故障返回 `500 SOURCE_SERVICE_UNAVAILABLE`，不能伪装为输入错误或对象不存在；注入审计 INSERT 后故障并核对来源名称、配置、密文、身份与验证时间全部未变，成功审计未提交。
- 编辑页始终不回填明文、密文或凭证片段，明文只在最短调用链存在，不进入长期页面状态、任务、缓存、日志或审计。
- 响应、日志、审计和页面均不泄露禁止披露项。

### AC-014 连接测试无同步副作用（安全场景）

**前置条件**

- 启用项目内存在接入源和既有资源、任务、最近/下次同步时间；模拟采集器可分别返回各资源类型 API 可达、权限不足、网络失败及包含虚构 AccessKey 的原始错误正文。服务器类型可分别控制阿里云实例/云盘和 AWS 实例/实例类型详情/EBS 补充 API；负载均衡可记录各列表、分页和监听器调用次数。

**操作**

1. 以系统管理员或所属项目管理员执行连接测试，覆盖全部模拟结果；以项目成员直接调用同一接口。
2. 比较测试前后的资源、资产状态、任务数、调度时间和生命周期时间。
3. 检查接口响应、应用日志、连接测试审计和页面状态。
4. 在接入源读取阶段注入内部数据库故障；另分别使用不存在和其他项目的来源标识请求连接测试。

**预期结果**

- 连接测试只进行认证、只读权限、网络和各资源类型 API 的轻量探测，返回各类型可达/不可达及中文安全摘要，不遍历或返回完整资源快照；ECS 以最小页面验证实例和云盘权限，EC2 以最小页面验证实例、实例类型详情和 EBS 权限。负载均衡只请求阿里云 SLB、ALB、NLB、GWLB 四个产品列表、AWS Classic 列表及一次 AWS ELBv2 列表，不读后续页或监听器，不写资源。
- 模拟 Probe 权限不足返回 `403 SOURCE_PERMISSION_DENIED`，认证失败返回 `502 SOURCE_AUTHENTICATION_FAILED`；身份识别的 `CLOUD_IDENTITY_UNAVAILABLE` 不得覆盖连接测试分类，响应与失败审计均不包含云原始错误。
- 来源读取内部故障返回 `500 SOURCE_SERVICE_UNAVAILABLE` 和固定中文摘要；不存在与跨项目来源保持相同 `404 SOURCE_NOT_FOUND`。读取失败不执行探测，资源、任务、凭证、同步计划和审计均保持基线，不泄露数据库错误。
- 不创建同步任务，不写资源，不更新最近/下次同步时间，不执行失联、恢复或删除判定；项目成员请求被后端拒绝且无副作用。
- 页面不把测试表示为同步结果，也不刷新资产或最近同步时间；审计只记录与实际测试一致的安全结果分类。
- 响应、日志、审计和页面均不出现原始错误正文、请求响应载荷、堆栈、凭证片段或其他禁止披露项。

## 同步任务与恢复

### AC-015 自动调度、周期和停用边界

**前置条件**

- 使用可控时钟准备同步周期边界值 4、5、10080、10081 及非整数；另有已到期/未到期、启用/停用的接入源，并为模拟采集器配置成功、部分成功和失败结果。

**操作**

1. 创建或编辑各周期样本，运行自动调度。
2. 分别完成自动成功、部分成功和失败任务；再完成手工失败及重试失败任务。
3. 在一个任务已排队及另一个任务运行中时停用其接入源。

**预期结果**

- 周期只接受 5 至 10080 分钟整数；默认值为 60。自动调度只为已启用且到期的接入源创建任务。
- 自动成功或部分成功按配置周期更新最近和下次同步时间；自动失败将下次执行推进到完成时间加周期，避免紧密重发。
- 手工或重试失败不改变既有自动计划。停用只阻止未来自动任务，不取消已受理的 `queued` 或 `running` 任务，既有任务继续进入终态。

### AC-016 手工排队、同源互斥与异源并行

**前置条件**

- 同一启用项目内准备接入源 A 与 B；模拟工作器可暂停任务执行。

**操作**

1. 对 A 发起立即同步并在接口返回后暂停工作器；对 A 再分别触发手工、自动和重试。
2. 同时对 B 发起同步并释放两个工作器。
3. 在页面观察任务从提交到终态的展示。
4. 在手工同步读取接入源阶段注入内部数据库故障，并分别请求不存在和跨项目来源。

**预期结果**

- 第一次手工请求先持久化并立即返回 `queued` 任务，采集在后台发生，接口不等待完整采集。
- 来源读取内部故障返回安全 `500 SOURCE_SERVICE_UNAVAILABLE`，不存在与跨项目来源保持同一 `404 SOURCE_NOT_FOUND`；读取失败不创建任务，不改变资源、凭证、同步计划或审计。
- A 已有 `queued` 或 `running` 任务时不创建任何同源新任务；自动、手工、重试遵守同一互斥规则。B 可并行执行。
- 触发稳定值仅为 `scheduled` 和 `manual`；普通手工为 `manual`，重试也为 `manual` 但有 `previous_job_id`。
- 页面先展示“排队”并轮询，只显示“排队、运行中、成功、部分成功、失败”五种状态；提交中禁止重复和冲突操作。

### AC-017 任务状态机与逐类型统计

**前置条件**

- 准备覆盖单个平台完整预期类型集合的模拟响应，包含新增、真实更新、恢复、失联和删除各一项；可直接尝试非法状态写入。

**操作**

1. 执行完整成功同步，观察状态流转、开始/完成时间、触发方式、逐类型统计和摘要。
2. 尝试跳过 `running`、从终态改写终态或改回运行中。
3. 对照实际资源变化核算每个尝试类型的新增、更新、恢复、失联、删除和失败数量。

**预期结果**

- 状态只从 `queued` 到 `running`，再到 `success`、`partial_success` 或 `failed`；非法跳转和终态改写被拒绝。
- 任务记录触发方式、开始和完成时间、全部资源类型统计、可选原任务标识及安全摘要。
- 每个尝试类型均有六项统计；成功类型失败数为 0，统计与真实资源及审计变化一致。
- 平台声明与采集结果保持固定顺序：阿里云必须为 `ecs`、`rds`、`slb`、`alb`、`nlb`、`gwlb`，AWS 必须为 `ec2`、`rds`、`clb`、`alb`、`nlb`、`gwlb`；任务统计是对象，只要求类型集合完整，不要求对象键顺序。任何缺失、重复、额外或旧 `elb` 类型均不能作为有效成功结果。

### AC-018 类型部分成功与失败隔离（安全场景）

**前置条件**

- 数据库中各资产模型及 SLB、CLB、ALB、NLB、GWLB 均有基线；模拟响应让一种类型成功新增和失联、一种成功无变化、一种返回含敏感载荷的采集失败；另准备服务器补充 API 权限不足而 RDS、负载均衡仍可成功采集的两平台响应，以及阿里云单产品失败、AWS 单类监听器失败响应。

**操作**

1. 执行同步直至终态，检查三类资产模型及每个具体负载均衡类型的资源、统计、任务摘要、调度时间和审计。
2. 在成功采集后、最终事务提交前读取资源，随后允许提交。
3. 检查接口响应、应用日志、审计和任务/资产页面状态。

**预期结果**

- 任务终态为 `partial_success`；失败类型只记失败数 1，其余五项为 0，资源和生命周期保持同步前状态且无失联、恢复或删除审计。
- ECS/EC2 的补充 API 权限不足只使服务器类型失败，采集器继续调用同平台的 RDS 与负载均衡；成功类型照常进入最终事务，凭证认证失效则整体终止且不保留局部结果。
- 阿里云任一负载均衡产品失败只隔离该产品；AWS `alb`、`nlb` 或 `gwlb` 的监听器失败只隔离对应类型。失败类型没有新快照，不触发失联、恢复或删除，其他完整类型仍可提交。
- 全部成功类型的所有变更、所有类型统计、任务终态、调度时间和审计在一个最终事务中同时可见，不按类型提前提交。
- 页面终态展示逐类型安全统计和中文安全摘要，仅提供允许的重试入口，不展示原始云错误。
- 响应、日志、审计和页面均不含原始错误、载荷、凭证或其他禁止披露项。

### AC-019 认证失败、整体失败、全部类型失败与未执行保护（安全场景）

**前置条件**

- 接入源已有正常和已失联资源；分别准备认证失败、整体采集失败、所有资源类型分别失败但 `Collect` 整体返回 `nil` 错误、空结果、缺少类型、重复类型、额外类型、旧 `elb` 类型、AWS ELBv2 列表失败和 ELBv2 未知类型，以及任务持久化后未被工作器执行的模拟条件，错误正文含虚构敏感字段；记录最近同步、最近发现和生命周期时间基线。

**操作**

1. 分别触发上述条件并检查任务、资源状态、时间、物理记录、统计、调度和审计；失败分支分别覆盖自动、手工和重试触发。
2. 检查接口响应、应用日志、审计和任务/资产页面状态。

**预期结果**

- 认证失败、整体采集失败、全部类型失败、空结果及类型集合不完整或重复均收敛为 `failed`，即使 `Collect` 整体错误为 `nil` 也不能写成 `partial_success`；已持久化但尚未执行的任务保持“排队”（`queued`），不伪造采集结果。
- 所有失败或未执行条件都不改变任何资源的资产状态、最近发现时间、失联时间或物理存储，不推进最近同步时间和生命周期，不产生资源变化审计；无效类型集合不得保留局部成功快照。
- 失败任务不保留资源变化或资产变化统计；全部类型失败仅可保留每个类型的失败数 1 和中文安全失败分类，不能生成新增、更新、恢复、失联、删除统计。自动失败只按 AC-015 推进下次计划，手工及重试失败不改变计划。
- AWS ELBv2 列表失败或出现未知类型时，`alb`、`nlb`、`gwlb` 必须同时安全失败且保留各自旧快照；不得把未知类型写为 `elb` 或任何已知类型。认证失败仍使全部类型整体终止。
- 响应、日志、审计与页面只包含“凭证认证失败”“云账号权限不足”“网络连接失败”等中文安全分类，不含原始响应或禁止披露项。

### AC-020 最终事务失败的完整回滚

**前置条件**

- 模拟全部资源类型成功并产生多项资源变化；在最终事务提交点注入数据库失败，记录任务和数据库基线。

**操作**

1. 执行任务直至注入点并触发提交失败。
2. 检查资源、端点、六项统计、任务状态、最近/下次同步时间和所有相应审计。

**预期结果**

- 最终事务中的全部资源和端点变化、统计、调度时间及审计一同回滚，不遗留任何成功类型的部分结果。
- 系统另起事务把任务收敛为 `failed` 并保存中文安全摘要；失败任务无统计。
- 任务状态、资源事实和审计相互一致，不存在描述未提交业务变化的审计。

### AC-021 失败与部分成功任务重试（安全场景）

**前置条件**

- 在不同接入源分别准备 `success`、`failed`、`partial_success`、`queued` 和 `running` 原任务，避免同源互斥干扰状态资格检查；`failed` 来自认证失败、整体采集失败或全部类型失败，`partial_success` 来自至少一个类型成功且至少一个类型失败，包括 EC2、RDS 或 CLB 成功但 AWS ELBv2 列表失败或出现未知类型。准备可重新启用的项目和全部类型成功的重试响应。

**操作**

1. 项目启用时分别请求重试五种状态的任务；让允许的重试进入终态。
2. 停用项目后重试原 `failed` 与 `partial_success` 任务，先断言被拒且未创建任务；由系统管理员重新启用项目后再次重试，使用全部类型成功响应完成任务。
3. 检查新旧任务字段和模拟采集器收到的资源类型集合。
4. 检查接口响应、应用日志、重试审计和任务页面状态。

**预期结果**

- 只有 `failed` 与 `partial_success` 可重试；每次重试新建 `queued`、`manual` 任务并记录 `previous_job_id`，不覆盖原任务的状态、统计、时间和摘要。
- 重试重新完整采集接入源配置的全部资源类型，不只采集原失败类型，并继续遵守同源互斥、项目归属、权限、平台边界和生命周期规则。
- 重试阿里云来源必须重新采集 `ecs`、`rds`、`slb`、`alb`、`nlb`、`gwlb`，AWS 必须重新采集 `ec2`、`rds`、`clb`、`alb`、`nlb`、`gwlb`；不得产生旧 `elb`。
- 项目停用期间重试被拒绝，不新增任务或成功重试审计；重新启用后符合资格的重试可完成为 `success`，原任务保持不变。
- 页面只为允许的终态展示重试操作，并保留原任务历史；响应、日志、审计和页面不含原始错误、凭证、JWT 或其他禁止披露项。

### AC-022 服务重启后的任务恢复（安全场景）

**前置条件**

- 数据库中一个接入源有已持久化 `queued` 任务，另一接入源有异常遗留 `running` 任务。保存人工任务的最小操作人快照后停用项目或接入源，并准备可注入的恢复查询、任务保存或审计失败。

**操作**

1. 重启服务并观察排队及异常遗留任务的恢复处理、资源变化和审计操作人。
2. 若项目已停用，先对被收敛任务发起重试并断言被拒，再由系统管理员重新启用项目；随后按规则发起重试并完成任务。仅接入源停用时按既有手工重试规则执行。
3. 检查接口响应、应用日志、审计和任务页面状态。

**预期结果**

- `queued` 任务恢复到正常执行流程，即使受理后项目或接入源被停用也继续进入终态；不会为停用对象创建新的自动任务。
- 遗留 `running` 任务收敛为 `failed`，摘要为“服务重启导致任务中断，可重新执行”这一类安全中文信息；停用项目内重试不创建任务，重新启用后才可按失败任务规则新建重试。
- 恢复查询、任务保存或审计任一步失败时服务拒绝启动，不开放不完整恢复状态下的接口。
- 无人工请求的恢复审计标记“系统任务”、操作人为空且不伪造 IP；人工请求仅沿用用户名和显示名称等最小审计快照，不传递 JWT、密码或完整用户对象。
- 响应、日志、审计和页面不泄露凭证、令牌、内部用户 ID 或其他禁止披露项。

## 资产模型与生命周期

### AC-023 新增与幂等刷新

**前置条件**

- 使用可控时钟；模拟同一接入源同一资源类型返回固定云端唯一 ID 和完全相同的稳定字段、原始属性及端点，并让同一云端 ID 分别作为 ALB、NLB、GWLB 返回。

**操作**

1. 首次成功同步，再推进时钟并重复两次相同成功同步。
2. 检查资源记录数、唯一键、项目归属、状态、首次/最近发现时间、业务更新时间、统计和审计。

**预期结果**

- 首次同步按“接入源 + 资源类型 + 云端唯一 ID”创建唯一记录，继承接入源项目，状态为“正常”，首次和最近发现时间正确。
- 重复同步始终更新原记录且只刷新最近发现时间，不新增重复资源，不改变首次发现和业务更新时间，不增加更新统计或产生无意义更新审计。
- 同一云端 ID 位于不同接入源或资源类型时是不同资源身份；同一平台或跨平台的 `alb`、`nlb`、`gwlb` 不得相互覆盖，`provider` 与接入源共同保持厂商边界；云端状态与 CMDB 资产状态保持两个独立维度。

### AC-024 三类模型、真实更新与同步维护权

**前置条件**

- 模拟 ECS/EC2、阿里云 RDS/AWS RDS，以及阿里云 SLB/ALB/NLB/GWLB、AWS CLB/ALB/NLB/GWLB 响应，分别包含实例类型、vCPU、内存、实例内外网 IP、已挂载云盘明细、数据库引擎/版本/实例规格/存储类型/已分配容量/端点、负载均衡网络类型/端点，并准备稳定字段、受管原始属性和端点变化。负载均衡样本覆盖单 Region 全分页、AWS ELBv2 一次列表分组、同云端 ID 的不同类型、阿里云产品级失败、AWS 单类监听器失败和未知 AWS 类型；磁盘样本覆盖系统盘、数据盘、重复/乱序返回、加密与未加密、挂载过渡态、必要字段缺失以及不纳入范围的临时本地盘；AWS 实例样本另覆盖空实例类型，AWS RDS 样本覆盖固定规格与 Serverless，阿里云 RDS 样本覆盖详情缺失。

**操作**

1. 成功同步两平台完整范围并检查三类独立模型、统一只读视图、服务器与数据库计算规格、服务器云盘明细、数据库存储规格和端点字段；验证五种负载均衡类型共享资产表且按资源类型隔离身份。
2. 模拟真实字段变化再次同步。
3. 分别让阿里云云盘或 RDS 详情 API、AWS 实例类型详情或 EBS API 失败，并让实例规格详情、实例类型、AWS 根设备名或已挂载磁盘必要字段缺失，检查对应类型结果和原有快照；混入未挂载、挂载中、卸载中和临时本地盘检查服务器过滤结果。
4. 通过页面和普通业务接口尝试修改原始属性、云端状态、资产状态、服务器规格、云盘明细、端点及域名解析 IP。

**预期结果**

- 计算、数据库、负载均衡分别只保存自身专属字段；服务器结构化保存实例类型、vCPU、内存 MiB、内外网 IP 和已挂载云盘明细，云盘按 ID 排序去重并记录系统盘/数据盘、类型、容量 GiB、设备名和加密状态。阿里云只接收 `In_use` 云盘，AWS 只接收 `attached` EBS；未挂载、挂载中、卸载中和临时本地盘均不保存。数据库结构化保存实例规格、可确定时的 vCPU 与内存 MiB、存储类型和已分配容量 GiB；未知规格容量为空而非 `0`，托管存储不构造逐盘明细。统一视图包含项目、接入源、平台、类型、云端 ID、名称、地域、可用区、云端状态、资产状态、各时间和原始属性等公共字段。
- 负载均衡完整同步只读取接入源配置的单个 Region，四个阿里云产品和 AWS Classic 均遍历至列表末页；AWS ELBv2 完整列表只调用一次，再按 `alb`、`nlb`、`gwlb` 生成相互独立的类型结果。不得因空页、不同类型或另一 Region 的结果漏记、混入或推进当前类型的生命周期。
- 任一服务器补充 API 失败或实例规格不完整时，ECS/EC2 类型失败且不覆盖原有规格和磁盘快照，也不触发该类型资源失联；其他成功类型仍按 AC-018 处理。
- 阿里云 RDS 详情失败或缺失、AWS 固定实例类型补充 API 失败时，RDS 类型失败且不覆盖原有规格与存储快照；AWS Serverless 或没有固定实例类型时 CPU、内存为空但其他 RDS 字段仍可成功同步。
- 端点随资源归属，保存类型、地址、端口、协议及最近成功解析 IP；地址可为 IP 或域名，解析 IP 不作为资源身份或固定属性。
- 稳定业务字段、受管原始属性或端点变化更新原记录，计入更新统计并生成更新审计。
- 页面及普通业务接口均为只读，不能人工修改云平台原始属性、云端状态、资产状态或端点；只有同步模块能维护这些字段。
- 不得因本场景声称已采集或结构化 Target Group、Server Group、后端服务器、健康检查、转发规则、证书、TLS 策略、监控或跨 Region 自动发现。

### AC-025 易变观测属性不虚增更新

**前置条件**

- 已有域名端点资源；模拟响应仅改变域名最近解析 IP，其他稳定字段、原始属性和端点定义不变。

**操作**

1. 推进可控时钟并执行成功同步。
2. 检查观测快照、最近发现时间、业务更新时间、更新统计和审计。

**预期结果**

- 只更新对应易变观测快照与最近发现时间，不修改稳定业务字段或业务更新时间。
- 不计入业务更新统计，不产生资源更新审计；动态解析 IP 不成为固定资产身份或固定属性。

### AC-026 成功采集触发失联

**前置条件**

- 某接入源同类型有正常资源 A 与 B；模拟该类型成功响应只返回 A，其他类型结果与判定隔离。

**操作**

1. 执行同步并检查 B 的状态、云端状态、失联时间、统计、审计和页面。
2. 用其他资源类型的空结果重复同步。

**预期结果**

- 仅在 B 所属类型成功采集且未返回 B 时，将其从“正常”改为“已失联”、写入失联开始时间、增加失联统计并生成审计。
- B 的云端状态保留最近有效值，不因失联被推断或改写；其他资源类型不能影响 B。
- 页面以“已失联”中文文本和非颜色标记展示，保留名称、云端 ID、接入源、最近发现时间及最近有效可展示属性，不显示为“已删除”。

### AC-027 失联资源恢复原记录

**前置条件**

- 已有状态“已失联”的资源及失联开始时间；模拟同接入源、同类型、同云端唯一 ID 再次出现。

**操作**

1. 执行成功同步并检查记录主键、状态、时间、统计、审计与页面。

**预期结果**

- 恢复原资源记录而非新建重复记录，资产状态改为“正常”，失联开始时间清空，最近发现时间刷新。
- 恢复统计增加并生成独立恢复审计；首次发现时间保持不变。

### AC-028 失联满 24 小时后的成功确认删除

**前置条件**

- 使用可控时钟准备刚失联、失联 23:59:59、正好 24:00:00 和超过 24 小时的同类型资源；可模拟成功空结果、认证失败、采集失败和只推进时钟。
- 另为项目和接入源删除分别准备三类资产的独立样本，覆盖正常、已失联及超过 24 小时但未经成功确认的资产，并保留端点和历史记录；分别准备 `queued`、`running` 和三个终态任务。

**操作**

1. 在各时间点只推进时钟或执行失败采集，再在时长届满前后执行同类型成功且仍缺失的采集。
2. 检查物理记录、删除统计、任务结果和审计保留。
3. 以系统管理员删除仍有上述资产依赖或活动任务的项目，以系统管理员和项目管理员删除对应接入源，并检查父对象、资产、端点、任务及历史记录。先停用待清理对象，验证停用不会清理资产；项目需要新建同步任务时先重新启用，再通过正常生命周期完成满 24 小时后的成功确认清理。
4. 三类资产全部清理且活动任务进入终态后重新删除父对象；另以并发同步或任务入队模拟删除检查后新增依赖的竞争，并直接触发数据库限制外键，验证不会通过级联删除绕过保护。

**预期结果**

- 定时器、认证失败、失败采集及届满前的成功采集均不物理删除资源。
- 只有资源连续失联满 24 小时后发生的同类型成功采集再次确认缺失，才在最终事务中物理删除，计入当前任务删除统计并生成独立删除审计。
- “已删除”不是在库状态；物理记录删除后，包含非敏感资源快照的审计仍长期保留。
- 任一正常或已失联资产仍依赖项目或接入源时，删除均被中文业务错误拒绝，保留父对象、资产、端点和历史记录，不产生成功删除审计；即使失联超过 24 小时也不能靠父对象删除跳过成功确认。
- 任一 `queued` 或 `running` 任务同样以稳定 `409` 阻止删除，三个终态任务本身不阻止；系统管理员的最高权限不能绕过资产、活动任务和生命周期不变量。
- 仅三类资产均无依赖且没有活动任务时才可按权限删除父对象；依赖检查、审计和删除保持事务一致性，先项目、后接入源的固定锁序与六个 `ON DELETE RESTRICT` 外键共同保证并发新增依赖不能被级联删除。停用与重新启用不替代资源生命周期清理，删除后审计仍长期保留。

## 审计与敏感信息

### AC-029 重要动作审计与业务一致性（安全场景）

**前置条件**

- 准备可执行全部重要动作的系统管理员、项目管理员、项目、用户、成员、接入源和模拟同步响应；可注入业务事务失败。

**操作**

1. 执行用户创建、资料/密码修改、角色/状态变化和删除；项目创建、资料/状态变化和删除；成员添加、变更和移除；接入源创建、编辑、凭证替换、启停和删除；连接测试；自动、手工和重试结果。
2. 执行资源新增、真实更新、失联、恢复和物理删除，并重复幂等刷新与易变观测刷新。
3. 对需要审计的人工业务变更注入事务失败。
4. 检查接口响应、应用日志、全部对应审计和相关页面状态。

**预期结果**

- 所有列明的重要动作都有统一审计；资源五种真实变化分别可追溯，连接测试和各触发任务结果可区分。
- 只有最近发现时间或易变观测变化不产生资源更新审计；采集失败不产生虚假的失联、恢复或删除审计。
- 业务变化与对应审计在同一事务提交或一同回滚；注入失败不留下成功审计，资源同步遵守 AC-018 和 AC-020 的最终事务边界。
- 响应、日志、审计和页面均不泄露禁止披露项，页面呈现的动作结果与服务端事实一致。

### AC-030 递归脱敏与安全错误收敛（安全场景）

**前置条件**

- 构造包含大小写及命名变体敏感键的嵌套对象与数组，值包含虚构密码、哈希、令牌、AccessKey、API Key、客户端 Secret、主密钥、密文、`Authorization`、云原始错误、正文、堆栈和用户数字 ID；包含一个尚未被统一敏感键分类识别的新敏感键。

**操作**

1. 让该载荷经过业务错误、连接测试、同步任务和审计详情持久化链路。
2. 对新增或重命名的敏感键先编写能失败的递归过滤回归测试，再加入共享敏感键分类并运行测试；检查发布前变更同时包含分类与回归测试，随后通过受测链路验证过滤。
3. 检查接口响应、应用日志与进程输出、数据库非凭证字段、审计、任务结果、测试输出/快照/夹具、代码仓库、页面状态和浏览器存储。

**预期结果**

- 统一过滤在返回、日志记录、持久化和审计前递归清理对象与数组中的敏感键、内部用户引用、原始云载荷和堆栈；各业务模块不维护各自的弱化过滤器。
- 新增或重命名敏感键在发布前已加入共享分类且回归测试通过；运行时递归移除已分类的键，不要求猜测未知字段语义，不引入审计字段允许列表。平台、资源类型、统计、安全分类和其他不敏感业务详情可保留。
- 四个安全检查面、数据库非凭证字段及浏览器存储均按执行约定验证禁止泄露；测试输出与快照不得回显受测敏感载荷。隔离测试夹具可保存明确虚构输入，测试材料与代码仓库不得包含真实秘密，自动测试只使用模拟云响应。

### AC-031 审计内容、授权筛选与稳定分页（安全场景）

**前置条件**

- 创建跨全局与两个项目的多页审计数据，包含相同发生时间记录；准备系统管理员、项目甲管理员和项目成员，以及人工和系统任务审计。

**操作**

1. 以系统管理员查询全局及各项目审计；以项目管理员查询项目甲；以项目成员直接请求项目甲审计。
2. 按上下文、时间范围、动作、操作人用户名、对象类型和公开对象标识组合精确筛选。
3. 获取第一页 `snapshot_id`，翻页期间插入新审计，再取后续页；随后改变筛选条件并继续使用旧快照尝试查询。
4. 检查接口响应、应用日志、审计查询记录和审计页面状态。

**预期结果**

- 系统管理员能查全局与所有项目；项目管理员仅能按路径查所属项目；项目成员无入口且接口被拒绝。后端每次按当前权限验证。
- 人工审计含操作人用户名/显示名称快照、可信来源 IP、动作、对象类型、稳定公开标识、脱敏详情、时间及适用的项目归属；全局操作项目为空。后台审计标记系统任务，操作人为空且不伪造 IP。
- 筛选用户和用户类对象只接受用户名；首次分页返回固定快照，按时间倒序再按审计 ID 倒序稳定排序，新记录不混入该快照。筛选变化时页面丢弃旧 `snapshot_id` 并新建快照；服务端把客户端提交的快照标识作为当前查询上界，无需持久化快照与筛选条件的绑定状态。
- 响应、日志、审计详情和页面不泄露内部用户 ID、凭证、原始错误或其他禁止披露项，无权限状态不保留数据。

### AC-032 审计仅追加、删除后长期追溯（安全场景）

**前置条件**

- 用户、项目、成员关系、接入源、任务与资源均已有审计；删除前已保存用户名、显示名称、项目名称、接入源名称、云端唯一 ID 等非敏感公开快照。

**操作**

1. 先按 AC-028 的正常生命周期清理全部依赖资产，再依次删除其他业务对象，并尝试更新或删除已有审计记录；不得借父对象删除清理资产。
2. 以仍有权限的角色查询历史审计；对缺少可信公开快照的旧记录尝试展示身份。
3. 检查接口响应、应用日志、历史审计和审计页面状态。

**预期结果**

- 审计只追加且长期保留，不因任何关联对象删除而级联删除；直接更新或删除审计被拒绝。
- 删除后仍可凭非敏感快照追溯操作人、项目和稳定对象标识；用户类对象使用用户名。
- 历史查询继续执行授权、敏感过滤和内部用户 ID 清理；缺少可信快照时不猜测、反查或暴露内部身份。
- 响应、日志、审计和页面均不泄露禁止披露项，无权限查询不保留历史详情。

## 页面、列表与可达性

### AC-033 导航、页面职责与项目切换隔离

**前置条件**

- 普通用户同时属于项目甲和项目乙，两项目具有不同资源、详情、筛选和待提交表单；准备可延迟返回的项目甲请求。

**操作**

1. 检查左侧导航、顶部项目切换及各角色可见页面；在项目甲打开列表、详情并填写未提交表单。
2. 切换到项目乙，在切换期间让延迟的项目甲请求返回，并检查浏览器缓存、路由和搜索候选。

**预期结果**

- 左侧导航分为“资产”和“管理”：资产含计算实例、数据库、负载均衡，管理含业务项目、云同步管理和审计日志；用户管理仅系统管理员可见。
- 三类资产页只读并展示各自资源类型专属字段；业务项目、用户管理、云同步管理和审计页职责与角色矩阵一致。
- 切换后立即清除项目甲列表、详情、筛选和待提交操作，以项目乙重新查询；迟到响应不能覆盖项目乙状态，任何瞬间都不展示或提交项目甲数据。
- 普通用户切换器、缓存、路由与搜索只包含当前已授权项目，不提供“所有项目”或泄露其他项目。

### AC-034 系统管理员“所有项目”与停用项目页面

**前置条件**

- 系统管理员可访问项目甲和乙；项目甲已停用且保留历史资产、任务、审计和接入源，项目乙启用。

**操作**

1. 选择“所有项目”查询资产、接入源、任务和项目审计，并尝试创建、编辑、启停、测试、同步、重试和删除。
2. 选择停用的项目甲，查询历史并尝试连接测试、手工同步、重试、自动任务创建、接入源配置修复、项目资料维护和重新启用。
3. 以项目甲普通成员执行同类请求。

**预期结果**

- “所有项目”只对系统管理员可见；记录均明确所属项目且仅允许跨项目只读，任何项目级操作均要求先选择具体项目，后端也拒绝以“所有项目”为操作目标。
- 停用项目保留项目归属及历史资料、资产、任务和有权审计的只读入口；禁止新连接测试、手工同步、重试和自动任务。
- 有接入源管理权限者仍能编辑已有配置以便修复；只有系统管理员能维护项目资料、重新启用或删除。普通用户不能因项目停用越权。

### AC-035 资源列表字段与组合筛选

**前置条件**

- 三类资产覆盖两个平台、多个项目、资源类型、正常/已失联状态，包含空名称和类型专属字段；负载均衡样本覆盖 `slb`、`clb`、`alb`、`nlb`、`gwlb` 及两平台同名类型；服务器样本包含 `c6a.xlarge`、4 vCPU、8192 MiB 内存以及三块合计 500 GiB 的云盘，数据库样本包含 `db.r6g.large`、2 vCPU、16384 MiB 内存和 `gp3` 200 GiB 存储，并包含 CPU、内存未知的 Serverless 样本。

**操作**

1. 分别打开三类专属资产页和系统管理员“所有项目”列表。
2. 组合改变云平台、资源类型和资产状态筛选，并观察请求与列表重置；打开负载均衡页，核对其请求依次包含 `slb`、`clb`、`alb`、`nlb`、`gwlb`，且不包含 `elb`。

**预期结果**

- 列表至少展示名称、云端 ID、接入源、平台、类型、地域或可用区、云端状态、资产状态和最近发现时间；“所有项目”必显所属项目，空名称记录仍显示云端 ID。
- 专属页预设并明确展示对应类型条件，只展示适用的专属字段；服务器规格显示为 `c6a.xlarge · 4 vCPU · 8 GiB`，磁盘汇总显示为 `3 块 / 500 GiB`；数据库规格显示为 `db.r6g.large · 2 vCPU · 16 GiB`，存储显示为 `gp3 · 200 GiB`，未知 CPU、内存或容量显示“未知”而非 `0`。
- 负载均衡页同时展示两个平台的 SLB、CLB、ALB、NLB、GWLB，类型使用官方大写缩写；审计中的这些资源类型同样使用官方大写缩写，不显示旧 `ELB`。
- 三项筛选可组合，每次变化都清除旧结果、回到第一页并由服务端重新查询，不在浏览器中对旧全集过滤。

### AC-036 单列排序与服务端稳定分页

**前置条件**

- 准备超过两页的资源，其中多个主排序值相同；记录每项“接入源 + 资源类型 + 云端唯一 ID”身份。

**操作**

1. 对允许列分别升序、降序查询并翻页、刷新；改变主排序列、方向、筛选、项目和每页数量。
2. 检查网络请求参数、服务端处理的数据量、页码、总数和跨页结果。
3. 制造请求失败后点击重试。

**预期结果**

- 每次只有一个主排序列，服务端固定追加资源身份作为次级排序；相同条件下翻页和刷新无重复、遗漏或抖动。
- 使用真实服务端分页并显示当前页、每页数量和总条数，不一次加载全部资源后浏览器伪分页。
- 主排序、方向、筛选、项目或每页数量变化回到第一页；翻页、刷新与失败重试保留当前有效筛选和排序条件。

### AC-037 列配置与失联展示

**前置条件**

- 存在正常和已失联资产；以同一用户名打开不同页面类型与项目上下文，准备另一用户名对照。

**操作**

1. 隐藏可选列、调整顺序、刷新后恢复默认；尝试隐藏接入源、资源类型、云端 ID、资产状态及“所有项目”的所属项目。
2. 检查列配置持久化内容和作用域，并查看失联资源。

**预期结果**

- 可选列可显示/隐藏、重排并恢复默认；资源身份三列、资产状态及“所有项目”的所属项目不可隐藏。
- 配置可按用户名、页面类型和项目上下文隔离持久化，不使用或保存用户数字 ID、凭证、令牌或资源敏感原始属性。
- 失联以中文文字和图标/形状等非颜色线索展示，保留身份、来源、最近发现时间与最近有效属性，不伪装成删除或因失败任务擅自标记。

### AC-038 表单、危险操作与页面完整状态

**前置条件**

- 为每个数据页和关键操作准备延迟、空结果、安全失败、权限撤销和提交中响应；准备必填缺失、格式错误、越界数值和无具体项目上下文表单。

**操作**

1. 遍历首次加载、刷新加载、空数据、失败、无权限和提交中状态，并在项目切换时观察旧数据。
2. 提交所有非法表单；在提交期间重复点击并触发冲突操作；分别让服务端成功或失败。
3. 对删除项目/接入源/用户、停用用户/项目和替换凭证执行取消与确认。

**预期结果**

- 加载不把旧项目数据当作新结果；空状态说明上下文和下一步；失败显示中文安全摘要与重试；无权限清除详情；提交中说明动作并禁用重复及冲突操作。
- 前端在提交前校验必填、格式、范围和具体项目上下文，每个可纠正字段有相关联中文提示；服务端结果返回后均重新查询事实，不靠客户端推测状态或权限。
- 危险操作确认明确对象、影响及不可逆/权限影响；取消不发送请求，确认后等待服务端结果，不能提前显示成功。

### AC-039 云同步页面凭证与任务安全状态（安全场景）

**前置条件**

- 当前具体项目中有经创建时联网识别并保存的脱敏接入源、可测试连接、各状态任务及包含虚构敏感原始错误的失败结果；创建和编辑模拟响应可延迟，并可返回成功或稳定中文失败。

**操作**

1. 打开创建与编辑接入源表单、连接测试结果、任务详情及重试入口；检查来源操作范围、页面状态和浏览器持久化。
2. 执行完整凭证创建、留空凭证编辑、完整凭证替换、连接测试、立即同步和允许/不允许的重试；创建和替换分别覆盖云身份认证、权限和网络失败。
3. 对新建和编辑分别覆盖：项目甲提交挂起后切项目乙并填写新弹窗；关闭旧弹窗后打开另一弹窗；项目甲提交失败、其刷新挂起后切项目乙，再释放旧刷新；提交挂起时执行同项目单平台或云同步管理轮询，再释放提交成功或失败。
   在同项目先后发出甲、乙两个创建或编辑请求，覆盖新建/编辑全部组合；让乙先完成并刷新，再让甲成功或失败。另使乙、甲各自刷新均挂起，先返回甲的较新快照，再返回乙的较旧快照，并覆盖两个提交均失败。
4. 检查接口响应、应用日志、审计和页面状态。

**预期结果**

- 接入源页展示启用状态、脱敏凭证状态、最近/下次同步时间，不展示稳定账号标识和验证时间。创建要求完整凭证并在完成联网身份识别前显示提交中；后端只有识别成功才保存接入源，页面成功后显示服务端事实。
- 编辑不回填任何凭证内容，留空保留原凭证，只有显式提交完整凭证并联网确认仍为原账号后才整体替换；提交中禁用重复及冲突操作。
- 创建或替换凭证的云身份认证、权限和网络失败使用同一安全错误码，并返回与类别对应的固定中文处理提示；连接探测继续使用其独立错误分类。
- 连接测试只显示逐类型可达性及中文安全摘要；立即同步先展示排队并轮询；终态显示逐类型安全统计，只有失败和部分成功提供新建任务式重试。
- 服务端成功或拒绝后页面均以重新查询结果为准，不显示伪成功或保留无权数据；项目切换立即清空旧来源、任务、错误和接入源弹窗，旧请求不得覆盖新项目数据或新的提交状态。
- 旧创建或编辑的迟到成功不得关闭新弹窗，迟到失败不得清空新输入；只清理该提交自身凭证。旧请求及其后续刷新不得重新加载项目甲覆盖项目乙，也不得在刷新结束后把项目甲错误或清理状态写到项目乙。当前有效请求失败仍须刷新服务端事实并展示安全错误。
- 同项目轮询不得使新建或编辑跳过提交后的事实刷新或安全错误提示。
- 同项目每个已发出提交完成后均独立刷新，不按最后启动者取消其他提交；甲、乙反序完成后，列表仍包含所有已提交事实和刷新时的外部变更。较早快照迟到不得覆盖最新快照，较早失败的迟到刷新不得覆盖最后完成的失败提示，两个提交持有的凭证对象均须清空。
- 凭证输入仅在提交所需的最小瞬时通道存在，并在关闭、取消、成功、失败、项目切换及组件卸载后清理；响应、日志、审计、长期页面状态及浏览器持久化存储不含稳定账号标识、验证时间、明文/密文凭证、AccessKey 片段、原始云错误、堆栈、令牌、内部用户 ID 或其他禁止披露项。

### AC-040 桌面、平板、视觉语义与键盘可达性

**前置条件**

- 准备常见桌面和平板视口；页面包含导航、项目切换、筛选、宽表格、分页、表单、图标按钮、动态状态和危险确认弹窗。

**操作**

1. 在桌面和平板视口检查全部核心页面，仅用键盘按逻辑顺序完成项目切换、筛选、排序、翻页、打开并取消确认弹窗。

## 部署与首次初始化

### AC-041 PostgreSQL 17 空库首次初始化（安全场景）

**前置条件**

- CMDB 处于项目初建且尚无已发布版本；准备 PostgreSQL 17 新建空数据卷，以及用于确认不受支持边界的非空数据卷和其他 PostgreSQL 主版本环境。
- 准备彼此不同的虚构 PostgreSQL 管理员密码和 `cmdb` 应用账号密码，以及独立的 JWT 与凭证加密密钥；所有值均不具备真实访问能力。
- 准备可检查的 `docker-compose.yml`、`Dockerfile`、`001_create_app_role.sh`、`002_schema.sql` 和应用镜像。

**操作**

1. 使用 `docker compose config --quiet` 校验完整环境，在新建空数据卷上启动 PostgreSQL 17 和应用，观察两个初始化文件的执行顺序及结果。
2. 检查数据库对象所有者、业务表、约束、索引、中文注释、接入源身份字段和账号唯一约束；检查是否存在结构版本表。
3. 使用 `cmdb` 应用账号执行正常业务增删改查，再尝试建表、改表或其他 DDL；检查长期应用容器的数据库环境。
4. 检查应用镜像中的可执行文件，并执行一次性首次系统管理员初始化；在已有任意用户后重复执行管理员初始化。
5. 检查部署文档与运行入口对已有数据库、已有数据卷和其他 PostgreSQL 主版本的处理边界；确认没有任何自动或手工结构转换入口。
6. 检查命令输出、容器日志、数据库内容和页面，确认管理员密码、应用密码、JWT 密钥及凭证加密密钥的传递与披露边界。

**预期结果**

- CMDB 只在 PostgreSQL 17 空库上执行首次初始化；Docker Compose 只通过新建空数据卷进入该流程。已有数据库、已有数据卷和其他 PostgreSQL 主版本不在支持范围内，不得被部署流程自动修改或转换。
- PostgreSQL 按文件名顺序先执行 `001_create_app_role.sh` 创建受限 `cmdb` 账号，再执行 `002_schema.sql` 一次性创建完整业务结构并授权业务读写；`001`、`002` 只表示初始化顺序，不表示结构版本。
- 初始化结果不存在结构版本表或版本记录；应用镜像只包含 `cmdb-server`、`cmdb-init-admin` 和前端静态文件，不提供数据库结构转换命令，应用启动过程也不执行 DDL。
- `resource_sources.cloud_account_id` 和 `identity_verified_at` 均为非空字段，“云平台 + 稳定云账号标识”由非条件唯一约束保护。
- `cmdb` 应用账号可完成正常业务读写，但不能执行 DDL；业务结构由 `postgres` 管理员拥有，长期应用服务只配置受限应用账号，不配置 PostgreSQL 管理员凭证。
- 首次管理员命令只保存 bcrypt 哈希，数据库已有任意用户后拒绝重复初始化且不覆盖身份。四个安全检查面均不泄露管理员密码、应用密码、JWT 密钥、凭证加密密钥、连接串或底层数据库错误。
